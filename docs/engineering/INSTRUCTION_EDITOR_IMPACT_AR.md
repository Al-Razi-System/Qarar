# محرر التعليمات المنسقة — تحليل الأثر قبل التنفيذ

## الرحلة والثوابت

المحرر الحالي نص عادي. المطلوب محرر مرئي مع تنسيق وحجم ولون وقوائم، تحرير
مصدر Markdown واستيراد .md ومعاينة مطابقة لعرض التقديم والمناقشة. التعليمات
اختيارية، لا تتغير صلاحيات التصنيف ولا حالات الحفظ والتنشيط أو متطلبات المرفقات.
المرحلة السابقة اختيار التصنيف؛ المعدلة تأليف تعليماته؛ التالية حفظ لقطة الموضوع
ثم قراءتها في التقديم والاجتماع. الفشل يبقي المدخلات؛ الحفظ وحده يستعمل معاملات
وأقفال وإيصالات API/RPC الحالية، ولا تُحفظ الكتابة خارج النموذج.

## العقود والمستهلكون

- الحقلان submission_instructions وdiscussion_instructions يبقيان نصًا في
  authoring وtopic_type_authoring_profiles_v2، بحد 10000 حرف مع علامة الصيغة.
- المحتوى المنسق الجديد يبدأ بعلامة qarar:markdown:v1 ثم سطر جديد. النصوص
  السابقة بلا علامة تُعرض حرفيًا ولا تُعاد كتابتها أو ترحيلها عند فتح المحرر.
- جميع العروض تستخدم قارئًا واحدًا: المعاينة، ملخص التصنيف، تفاصيله، مقدم
  الموضوع، الجلسة الحية. النسخ التاريخية تبقى ثابتة بالمشغل الموجود.
- لا API/RPC أو جداول أو وظائف خلفية أو مشغلات أو مهام أو صلاحيات جديدة.
  لا تعديل ترحيل سابق ولا إدخال معرّفات. المصدر المحلي للـ.md قراءة فقط، وليس
  رفعًا إلى مخزن الأدلة. استيراد ملف يستبدل نص الحقل صراحة ولا يمس الحقل الآخر.
- مكتبات محرر وتحويل Markdown بدل execCommand أو تحليل Markdown يدوي.
  العرض يستعمل شجرة منقاة ولا يقبل scripts/events/iframes/صور تتبع أو CSS حرًا.
  اللون والحجم وحدهما على span يمران بقائمة تحقق مستقلة. روابط الويب الآمنة فقط.

## التحقق والرجوع

اختبار فاشل أولًا للمعاينة المنسقة ومنع XSS؛ اختبارات تبديل مرئي/مصدر/عرض،
تغيير النص خارجيًا، استيراد ملف ونوعه وحجمه، حد الحقل، حفظ وإعادة فتح وألوان
وأحجام، نسخ تاريخية والنص القديم. اختبار سياق التقديم والجلسة والصلاحيات من
DB81/82 والعقود الحالية. فحص متصفح بعرض 390px ومكتبي، lint/typecheck وبوابة
سياسة التطوير. لا إنتاج قبل بوابات الإصدار العامة (DB14 لديه خمسة إخفاقات سابقة).
الرجوع بإصلاح أمامي لقارئ العلامة، وليس عرض العلامة أو HTML للمستخدمين أو حذف النصوص.

## نتيجة التنفيذ والتحقق

- أُضيف محرر Tiptap مرئي بالهوية الموحدة، مع عناوين وعريض ومائل وتسطير وقوائم
  واقتباس ومسح التنسيق وتراجع/إعادة، وحجم 12–32 ولون النص. مصدر Markdown
  والاستيراد المحلي والمعاينة في المكوّن نفسه. الاستيراد الفاشل يحفظ النص السابق.
- فشل اختبار التنسيق أولًا مع القارئ النصي القديم. نجح بعد ربط جميع مستهلكي
  TopicInstructions بقارئ Markdown المنقّى المشترك. لا dangerouslySetInnerHTML.
- نجحت فحوص الواجهة الستة (16 تحققًا)، ثم الاختبارات الإضافية للمحرر والحدود
  والنموذج (10 تحققات)، والمحرر وعقود governance-model وtyped-topics (17 تحققًا).
  لا تُجمع الأعداد لأنها تشمل بعض الاختبارات المتكررة.
- DB81: 23 تحققًا للنص القديم والحفظ والتوريث والصلاحيات. DB82: 31 تحققًا بعد
  استخدام تعليمات Markdown فعلية في السيناريو؛ تشمل التحضير واللقطة التاريخية
  وقراءة الاجتماع ومنع الاطلاع غير المخول، دون تغيير سجل حقيقي.
- اجتاز المتصفح الدومين التطويري عبر مستأجر معزول: استيراد .md وعنوان وعريض
  ولون/حجم، تحرير مرئي، معاينة، حفظ، تعديل ونشر مباشر، إعادة فتح، تقديم موضوع
  وعداد الموضوعات وتعطيل/إعادة تفعيل، ومعاينة مكتبية 1440 وهاتف 390 دون overflow.
  حُظر حساب الاختبار بعد نهايته وحُفظ أثره التدقيقي. صور /tmp/qarar-topic-requirements-*
  فُحصت بصريًا. لا تغيير لبيانات الجامعة.
- typecheck ناجح؛ lint بلا أخطاء مع التحذيرات الستة السابقة خارج نطاق العمل؛
  test:development-governance وترميز الوثائق ناجحان.
- التشغيل الأول بالتوازي ضغط ذاكرة الخادم وأدى إلى timeouts؛ أُعيدت اختبارات
  الواجهة بالتتابع (عامل واحد) ونجحت، ثم أعيد المتصفح. لا توسيع مهلات اختبارات الوحدة.
- npm audit يبلّغ 15 مشكلة في شجرة الحزم الحالية، وليس في حزم المحرر الجديدة؛
  لم تُغيّر إصدارات الحزم القائمة. لا audit fix شامل ولا نشر إنتاجي؛ تبقى بوابات
  DB14 السابقة ومراجعة ثغرات التبعيات ضرورية للإصدار العام.
