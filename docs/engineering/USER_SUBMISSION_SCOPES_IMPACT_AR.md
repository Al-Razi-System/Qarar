# نطاق تقديم المستخدم — تحليل الأثر قبل التنفيذ

المطلوب جهة عمل مستقلة ونطاق تقديم شخصي متعدد الاختيار: مجلس محدد أو مستوى
مجالس، مع شمول التفرعات اختياريًا. لا أسماء جامعات أو كليات ثابتة ولا شجرة مجالس
إضافية. مجلس مرتبط بوحدة تنظيمية يستمد فروعه من تبعية الوحدة؛ المجلس بلا وحدة
لا يملك فروعًا ضمنية، ويظهر ذلك للمستخدم. اختيار مستوى يحدد المجالس المطابقة
له وفروعها عند الاختيار. تُستعمل governance_class_id القائمة، لا اسم النوع.

المرحلة الأولى هنا إدارة نطاق المستخدم الموجود من قائمة المستخدمين، بما فيها
الحساب المنتظر للتفعيل. ربط النموذج أثناء إنشاء هوية Auth، تعدد الأدوار، وكلمة
المرور والصورة تبقى مراحل لاحقة؛ لا حفظ جزئي صامت في رحلة الدعوة الحالية.

الثابت: جهة العمل لا تمنح صلاحية. نطاق التقديم يمنح topics.create للمجالس
المطابقة فقط، لا عضوية أو قيادة أو قراءة موضوعات الغير أو إدارة أو تصويت.
التصنيف ومساره والمرفقات والتفعيل تبقى شروطًا إضافية مستقلة. القديم يحتفظ
بصلاحياته: النطاق الجديد إضافي ولا يسحب الصلاحيات الممنوحة عبر الأدوار.

العقود: API /admin/users/[userId]/submission-scope، RPC قراءة/حفظ IAM جديدان،
امتداد ملف المستخدم ومحددات نطاقه مع علاقات مؤسسية FK، وhas_permission و
actor_has_permission وإظهار topics.create في access context. get_topic_form_options
وprepare/create typed يستعملون الصلاحية الحالية، دون مسار يتجاوز العقود السابقة.
لا مهام أو بريد أو تغيير حالات مستخدم أو موضوع أو نسخ تاريخية.

الحفظ: مدير نظام نشط داخل المؤسسة فقط في هذه المرحلة؛ يمنع مدير نطاق جزئي
من توسيع سلطة مستخدم عبر المؤسسة. قفل ملف المستخدم ومعاملة واحدة، expected
revision للرفض المتقادم؛ إعادة نفس القيم بنفس النسخة الحالية تظل عملية صريحة
بدون ازدواج محددات. نجاح يزيد النسخة ويسجل قبل/بعد وفاعل، فشل يعيد كل شيء.
معاينة القواعد في الواجهة تشرح الاتجاه والفروع، والقاعدة النهائية في DB.
النقل في الشجرة وتفعيل/تعطيل المجالس يغير النطاق الفعلي مباشرة؛ مدقق الشجرة
القائم يحمي الدورات. لا نسخ مجالس أو عضويات لكل فرع.

الاختبار قبل الكود: DB يفشل لغياب عقد حفظ/حساب النطاق؛ مخول وغير مخول ومؤسسة
أخرى، مجلس/مستوى/فروع/غير مرتبط، أكثر من اختيار، حفظ متقادم، إزالة منح مع حفظ
عضوية قديمة، تعطيل المستخدم والمجلس، فشل حفظ يحفظ المدخلات، هاتف ومكتبي.
DB79/82 ومستهلكو صلاحية IAM محميون باختبارات جوار. الترحيل أمامي في قاعدة
التطوير المعزولة فقط، مع توثيق الانحراف والبصمة؛ لا إنتاج مع بوابات عامة فاشلة.

## المتبقي للإدارة الكاملة

1. اكتمل الربط في خطوة إعداد بعد إنشاء الهوية والدعوة داخل النافذة نفسها؛
   انظر `USER_CREATION_SCOPE_HANDOFF_AR.md`. إصدار بروتوكول إنشاء كامل بإيصال
   دائم لاسترداد رد إنشاء مفقود ما زال غير منفذ؛ حالة عدم التأكد تمنع تكرارًا أعمى.
2. إنشاء مباشر بكلمة مرور أولية أو دعوة، وفق صلاحية المدير ومسار تفعيل واضح.
3. إدارة أدوار المستخدم المتعددة دون خلطها بنطاق التقديم أو الوحدة الوظيفية.
4. تغيير كلمة المرور والصورة من الملف الشخصي بضوابط التحقق والرفع.
5. عرض جهة العمل وملخص النطاق في جدول المستخدمين وتوحيد نموذج تحريره.
6. معالجة بوابات السجل وDB14 في دفعة سلامة مستقلة قبل الإصدار الإنتاجي.
