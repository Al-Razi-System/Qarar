# ربط إنشاء الحساب بجهة العمل ونطاق التقديم

## خريطة الأثر قبل التنفيذ — 9 أكتوبر 2026

الرحلة السابقة: إدارة المستخدمين، إنشاء هوية Auth وملف مستخدم غير نشط ودعوة
تفعيل عبر iam-admin. الرحلة التالية: حفظ نطاق المستخدم ثم تفعيل الدعوة وتقديم
موضوع إلى مجلس يسمح به النطاق. يجب ألا يعني نجاح الإنشاء أن النطاق حفظ.

الثابت: لا عضوية وهمية لمنح التقديم، ولا تفعيل ضمني للحساب، ولا إعادة إنشاء
الحساب عند فشل حفظ النطاق. جهة العمل مستقلة عن العضوية. الاسم والبريد ضروريان؛
تفاصيل العمل والعضوية الأولية اختيارية. لا تعرض حقولًا لا يحفظها العقد:
full_name_en وstart_date غير مدعومين في أمر الإنشاء الحالي، فتزال مدخلاتهما
المضللة؛ لا تمس أسماء أو عضويات قديمة.

المستهلكون: CreateUserForm وUsersWorkspace، ثم UserSubmissionScope المشترك
ومساره API وRPC قراءة/حفظ النطاق. عقد POST /api/admin/users وEdge iam-admin
وservice_finalize_invited_user وservice_issue_activation_invitation تبقى كما هي.
نجاح موثق: account_created=true وinvitation_sent=true وuser_id UUID. المخول
بإنشاء الحساب ليس بالضرورة مخولًا بمنح النطاق؛ خيار الاستكمال لمدير النظام
فقط وفق الإشارة القائمة من الصفحة، وRPC يحمي الحفظ في السياق نفسه.

الحالات: قبل الإنشاء لا هوية، أثناءه منع النقر المكرر، بعد تأكيده مستخدم غير
نشط مع دعوة ونطاق لم يحفظ. تنتقل الواجهة إلى إعداد الجهة والنطاق للحساب نفسه.
الحفظ الناجح ينهي النافذة ويحدث القائمة؛ الفشل يبقي النموذج والإيصال ويمنع
الرجوع لإنشاء حساب ثان. عند انقطاع رد الإنشاء أو رد 5xx/استجابة نجاح ناقصة
لا نكرر الطلب تلقائيًا: تظهر حالة عدم تأكد مع رابط قائمة المستخدمين للتحقق.
الإغلاق بعد الإنشاء لا يتراجع عن الهوية أو الدعوة، ويشرح موضع الاستكمال.

التخزين: لا جدول أو ترحيل أو بيانات إصلاح جديدة. لا نغير حالات Auth أو توكنات
التفعيل أو الأدوار القائمة. لا سجل تكرار إنشائي جديد؛ ما زال استرداد نتيجة
إنشاء فُقد ردها يحتاج تحققًا من القائمة. التكرار الآمن بالنطاق متوفر من المرحلة
الأولى. لا ندمج عمليات الشبكة في معاملة وهمية ولا نخفي فشل إرسال البريد.

الاختبارات أولًا: نموذج يفشل حاليًا لعدم الانتقال إلى نطاق الحساب المنشأ؛
مخول وغير مخول بالنطاق، نجاح بلا UUID/استجابة غير JSON، فشل إنشاء يحتفظ
بالمدخلات، نقرتان سريعتان، فشل نطاق لا يعيد POST، النجاح يغلق نافذة الإنشاء.
اختبارات النطاق القائمة وDB83 تحفظ التبعيات التالية؛ متصفح تطوير معزول يفحص
النافذة والهاتف ويستعمل أمر إنشاء حقيقي بدعوة بريد تجريبية، لا حساب جامعة.
قائمة النشر تبقى محجوبة بانحراف السجل وبوابات DB14 السابقة؛ لا إنتاج.

## نتيجة التنفيذ والتحقق

- ربط الإعداد بعد الإنشاء داخل النافذة نفسها، مع اسم صاحب الحساب ومعاينة
  النطاق المشتق. الحفظ الناجح يغلق نافذة الإنشاء ويحدث القائمة.
- لا يكرر فشل نطاق التقديم أمر إنشاء الهوية. يمكن الإغلاق والاستكمال من عمليات
  المستخدم. المدراء الجزئيون لا يحصلون على شاشة منح نطاق لا تسمح لهم RPC بحفظه.
- تحقق من أعلام الإنشاء والدعوة وUUID قبل الانتقال. النتيجة غير المؤكدة توقف
  تكرار أمر الإنشاء وتتيح التحقق من القائمة؛ لا إصلاح بيانات أو استرداد تلقائي.
- الاسم والبريد ظاهران؛ معلومات العمل الإضافية والعضوية الأولية تحت أقسام
  اختيارية. أزيل حقلا الاسم الإنجليزي وتاريخ البدء غير المدعومين بالعقد الحالي.
- اختبارات الواجهة والعقود والمعاينة وجدول المستخدمين: 20/20؛ منها رفض مدخل،
  نجاح ناقص، استجابة غير JSON، مدير جزئي، واستكمال الحساب نفسه.
- IAM Edge: 19/19؛ DB44 تفعيل الحساب: 12/12؛ DB83 نطاق التقديم: 27/27.
- اختبار المتصفح المعزول المحدث نجح بإنشاء حساب حقيقي ودعوة تجريبية: فشل حفظ
  نطاق محاكى، إعادة الحفظ دون إنشاء حساب آخر، إغلاق النافذة وتحديث القائمة،
  والحساب يظل غير نشط. حفظ وفحص النطاق بهوية الموظف ومنع رفع الصلاحية نجحا.
- فحص 1440 و390px دون تمرير أفقي؛ الصور `/tmp/qarar-create-user-desktop.png`
  و`/tmp/qarar-create-user-mobile.png`. لا حسابات جامعة تغيرت؛ حسابات الاختبار
  المعزولة حظر دخولها بعد الاختبار مع الاحتفاظ بسجلات التدقيق والدعوة.
- الفحص المتزامن lint/Vitest ضغط الذاكرة الكاملة وسبب مهلتين؛ أعيدت اختبارات
  الواجهة بالتتابع بالحد نفسه 15 ثانية ونجحت جميعها؛ لم يغير حد الاختبار.
- lint بلا أخطاء مع ستة تحذيرات سابقة، typecheck ناجح، وبوابة development-governance
  ناجحة. لا ترحيل جديد ولا نشر إنتاجي. بوابات DB14 وانحراف سجل الترحيلات السابق
  ما زالت بحاجة إلى دفعة سلامة مستقلة.

## المتبقي

إنشاء مباشر بكلمة مرور أولية، إدارة أدوار متعددة، الملف الشخصي، وإيصال إنشاء
دائم يعيد نتيجة الهوية عند فقد ردها. لا تعني واجهة الإعداد الحالية اكتمال هذه
العمليات أو تفعيل حساب الدعوة مباشرة.
