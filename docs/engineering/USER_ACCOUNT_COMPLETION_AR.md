الإنشاء الحالي بدعوة فقط، ودور أولي واحد. نطاق التقديم منفصل ويُحفظ بعد

## خريطة أثر الدفعة الحالية قبل التنفيذ

- الرحلة: جلسة مستخدم نشط ← حسابي ← تعديل بياناتي أو تغيير كلمة مروري ←
  تحديث هوية الشريط أو تسجيل الدخول بكلمة المرور الجديدة.
- الثابت: المستخدم لا يحدد UUID أو بريد صاحب التعديل؛ يستخرجان من الجلسة
  و`get_my_account`. تعديل الاسم لا يمنح دورًا أو يغير الوحدة أو المؤسسة.
- العقود المثبتة: `api_v1.get_my_account()`، و`update_my_profile` بأربعة
  معاملات نصية؛ تحققنا من تعريفهما في قاعدة التطوير. كلاهما يقيدان المستخدم
  إلى هويته النشطة ومؤسسته. تحديث الملف يسجل `iam.self.profile_update`.
- المستهلكون: صفحة جديدة `/admin/account`، API `/api/account` و`/api/account/password`،
  قائمة الحساب والشريط الجانبي. كلمة المرور تستخدم GoTrue بهوية المستخدم،
  وليس service_role أو تغيير حساب يختاره العميل.
- الصلاحيات: المستخدم النشط لنفسه؛ جلسة مفقودة أو MFA غير مكتملة مرفوضة.
  كلمة المرور الحالية مطلوبة وتتحقق عبر تسجيل دخول مستقل مع حماية معدل
  المحاولات القائمة. يُستخدم رمز الجلسة الأصلي لتحديث كلمة المرور كي لا
  ننزل ضمان MFA إلى جلسة إعادة التحقق الجديدة.
- قبل الفعل: بيانات محفوظة وكلمة مرور قديمة. بعده: بيانات محدثة أو كلمة
  مرور جديدة وتسجيل خروج. فشل التحقق لا يغير شيئًا. انقطاع رد تغيير كلمة
  المرور نتيجة غير مؤكدة: يجب إرشاد المستخدم إلى تجربة الجديدة لا إعادة
  إرسال عمياء. فشل إلغاء الجلسات لا يُعرض كفشل تغيير كلمة المرور.
- البيانات القديمة: لا ترحيل ولا تغيير في الأدوار أو الدعوات أو الحسابات
  الحالية. الصورة ليست حقل URL عشوائيًا؛ رفعها يحتاج عقد تخزين خاصًا لاحقًا.
- الاختبارات أولًا: عدم قبول هدف عميل؛ تحقق كلمة المرور الحالية؛ رفض عدم
  الصلاحية/كلمة ضعيفة/هوية تحقق مختلفة؛ فشل الخادم؛ حفظ البيانات والرسائل
  محليًا؛ ثم رحلة متصفح معزولة desktop/mobile، وفحوص النوع والlint.

## الأعمال التالية المطلوبة، غير المكتملة بهذه الدفعة

1. قائمة أدوار متعددة في الإنشاء والتعديل والتعطيل مع حفظ التاريخ وحماية
   آخر مدير نظام، وعدم الخلط بين أدوار التشغيل وعضويات المجالس.
2. دور مقدم موضوع/معاملة ونطاقه، وعرض مجالس النطاق الفعلية للمقدم مع
   تقاطع تصنيف الموضوع؛ مراجعة الأنواع مقابل المستويات التنظيمية.
3. رفع الصورة الشخصية إلى تخزين مقيد بالمالك مع حدود الحجم والنوع
   وسياسة القراءة، ثم عرضها في الشريط.

لا تُعرض أي من هذه النقاط كمنفذة قبل اختبار الرحلة فعليًا. لا نشر إنتاجي
ضمن هذه الدفعة؛ بوابات الانحراف والاختبارات السابقة تبقى مطلوبة.
