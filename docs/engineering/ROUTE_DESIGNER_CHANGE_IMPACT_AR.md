# مصمم مسارات الموضوعات — أثر التغيير

## تصحيح حدود الملكية — قرار المستخدم اللاحق

المسار المشترك يملك ترتيب المجالس فقط. عمل المجلس ونتيجتا القبول والرفض تملكها
نسخة نوع الموضوع، لكل مرحلة. لا نغيّر قوالب المحرك القديمة أو العمليات الجارية.
قالب الترتيب الجديد موسوم layout_only، ولا يجوز إنشاء workflow_instance منه مباشرة؛
عند حفظ تصنيف يربط به، يولّد الخادم نسخة تنفيذية مستقلة بسياسة التصنيف ويحتفظ
بمرجع قالب الترتيب وسياساته في binding. لا تُعرض النسخ التنفيذية الداخلية كمسارات
مشتركة. فشل الحفظ يتراجع عن توليدها أيضًا؛ إيصال التكرار يبصم مدخل التصنيف الأصلي.

المستهلكون: API مصمم المسارات، save_governance_bundle_draft_v2، خيارات التأليف،
topic_type_workflow_bindings_v2، معاينة المسار الحالية، ومحرك التنفيذ الحالي. القوالب
القديمة تبقى قابلة للقراءة ولا تتحول تلقائيًا إلى قوالب ترتيب فتفقد نتائجها.
الاختبار: تصنيفان بقالب واحد وسياسات مختلفة لا يغيّر أحدهما الآخر، تكرار الطلب،
التراجع الذري، منع تشغيل قالب ترتيب مباشرة، والقوالب القديمة دون stage_policies.

الإحالة في الاجتماع مهمة مؤجلة صريحة لمرحلة واجهات الاجتماعات: إجراء على الموضوع
ذاته بعد المناقشة، جهة وسبب وأدلة، صلاحيات سياقية، أثر بالمحضر وسجل الزيارات.
لا ندّعي تنفيذها في هذه الحزمة ولا نضع لها زرًا غير عامل أو انتقالًا ثابتًا بالقالب.

## الرحلة والثوابت

تجهيز الوحدات والمجالس ← تأليف مسار ← ربط تصنيف الموضوع بالنسخة النشطة.
المسار للموضوع وليس للبند. يسمح تأليف المسودة بمجلس غير نشط؛ جاهزية التنفيذ
تُفحص في سياق الموضوع بواسطة محلل المجالس الحالي. لا تتحول المسودة إلى مسار
متاح للتصنيفات إلا بالتنشيط الصريح والتحقق البنيوي. لا تُطلب معرفات يدوية.

## خريطة الأثر قبل التنفيذ

هذه الخريطة توثّق النسخة الأولى قبل تصحيح الملكية أعلاه؛ بنود النتائج والإحالة
واستهلاك التصنيف دون تعديل مستبدلة بالقرار اللاحق وعقود الفصل الجديدة.

- واجهة مستقلة `/admin/workflows` ورابط في الشريط الجانبي؛ لا نخلطها بمحرر اللوائح.
- عقدا `admin_get_route_designer_v2` و`admin_save_route_designer_v2` عبر API اللوائح
  الحالي مع رسائل أخطاء مستقلة. الإذن `governance.workflows.manage` في المؤسسة.
- الجداول الحالية: workflow_templates وworkflow_template_versions وsteps وtransitions؛
  أعمدة إضافية للمرجع وإيصال الحفظ ومواصفة المحرر، دون إعادة كتابة البيانات القديمة.
- يستخدم الحفظ معاملة واحدة، قفل المسار، مراجعة تفاؤلية، ومفتاح تكرار مرتبط بالفاعل
  والمؤسسة. كل حفظ ينشئ لقطة مسودة جديدة؛ النسخة النشطة والموضوعات الجارية لا تتغير.
- التنشيط يستخدم المدقق والمحرك الحاليين، ويحفظ النسخ السابقة متقاعدة دون حذفها.
- يستهلك تصنيف الموضوع النسخ النشطة الحالية دون تغيير عقده. لا تعديلات على التصويت
  أو المحاضر أو الجدولة أو صلاحيات معالجة الموضوع في هذه الحزمة.
- المسارات القديمة ذات الشروط المتقدمة تعرض للقراءة ولا تُحوّل إلى نموذج مبسط فاقد.
- النتائج: قبول إلى مرحلة أو اكتمال، رفض إلى مرحلة أو إنهاء، إحالة إلى مرحلة سابقة.
  الإحالة ليست تعديلًا يدويًا للنتيجة؛ صلاحيات التنفيذ الحالية تبقى دون توسعة.
- لا مهام مجدولة أو إشعارات جديدة. التدقيق عبر emit_audit_event الحالي.

## الفشل والتحقق والإصدار

الفشل يتراجع ذريًا ويبقي المدخلات في المحرر؛ التعارض يتطلب إعادة تحميل صريحة.
اختبارات قاعدة بيانات قبل التنفيذ: غياب العقد، المسودة بمجالس غير نشطة، المرجع
التلقائي، التكرار، التعارض، العزل والصلاحيات، الرسم والنسخ التاريخية والتنشيط.
اختبارات واجهة: ترتيب المراحل والإحالة ورسائل الفشل وحفظ المدخلات؛ اختبار متصفح
على سطح مكتب وعرض ضيق. الاختبارات المجاورة: قوالب المسارات، خيارات تصنيف الموضوع،
وحل المجلس حسب الوحدة. لا نشر إنتاجي؛ ترحيل أمامي على قاعدة التطوير المعزولة فقط.
الرجوع بتعطيل الرابط الجديد؛ تبقى العقود والنسخ التاريخية صالحة.
