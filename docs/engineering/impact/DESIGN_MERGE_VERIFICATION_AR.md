# دمج أساس التصميم وإغلاق عوائق التحقق — 2026-10-09

## خريطة الأثر قبل التنفيذ

المطلوب دمج PR130 مع دفعة الأدوار ونطاق التقديم، لا تغيير قواعد الموضوع أو
عضوية المجلس أو حالات الحساب. نحفظ الدفعة الوظيفية في التزام مستقل قبل الدمج.
تتأثر الترويسة العامة والخط وCSS والمكونات المشتركة وlint؛ لا RPC أو ترحيل
تجاري في فرع التصميم. نفحص الدخول ثم المستخدمين والمجالس والاجتماعات بعرض
مكتبي و390px، وتحميل الخط المحلي والأخطاء، ثم الرحلات الوظيفية متعددة الحسابات.
الفشل يوقف التسليم؛ الإصلاح الأمامي مستقل ولا يطمس عمل المطور الآخر.

## سجل الترحيلات

الفحص أعاد إنتاج 17 اسمًا رقميًا من 8 أكتوبر يقابلها في المصدر اسم كامل.
لا يجوز إعادة تنفيذ الترحيلات أو استبدال بصماتها لمجرد تمرير الفحص. أداة
إصلاح محدودة بالتطوير تفحص مطابقة SHA256 أولًا وغياب الاسم النهائي، ثم
تعيد تسمية السجل فقط في معاملة مقفلة وتحتفظ بالبصمة ووقت التطبيق. لا تغير
جدول أعمال أو مستخدمًا أو بيانات جامعة. تحفظ تقرير قبل/بعد محليًا للتدقيق.
تكون قابلة لإعادة التشغيل وترفض اختلاف البصمة أو التباس الاسم أو قاعدة إنتاج.
المستهلك هو فحص migration-drift؛ تختبر المطابقة والرفض والتكرار قبل التطبيق.

## عطل الاستجابة المعاد إنتاجه

اختبار المتصفح بعد الدمج كشف عرض قسم الدخول 425px عند شاشة 390px؛ العمود
الضمني في شبكة AuthLayout يستخدم حد المحتوى الأدنى بدل عرض الشاشة. الإصلاح
تحديد عمود واحد minmax(0,1fr) قبل التخطيط المكتبي، دون إخفاء المحتوى أو
تغيير عقد الدخول. يحمي اختبار المتصفح تحميل الخط وعدم التجاوز، ويعاد اختبار
الدخول وكلمة المرور المؤقتة بعده. لا تغيير في الحالات أو صلاحيات الحسابات.
ويزال حد المحتوى الأدنى الافتراضي من fieldset وحاوية النموذج بـ min-w-0؛
لا تغيير في الحقول أو التنسيق أو التحقق من الاعتماديات.
رحلة كلمة المرور المؤقتة أعادت إنتاج المشكلة نفسها في fieldset الاستبدال؛
يطبق عليه الإصلاح نفسه دون تغيير متطلبات الكلمة أو الجلسات.
