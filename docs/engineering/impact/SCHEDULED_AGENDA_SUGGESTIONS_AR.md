# ارتباط جدولة التصنيف بمقترحات جدول الأعمال

## تحليل الأثر قبل التنفيذ

الثابت: لا يُعد التصنيف مصدرًا تلقائيًا للمقترحات دون توقيت. إلغاء الجدولة يلغي
اختيار الإضافة التلقائية في المحرر، ويرفض الخادم الجمع بينهما. لا ينشأ موضوع أو
بند نهائي أو جلسة منعقدة بسبب عرض المقترحات.

الرحلة: إعداد تصنيف وجدولته وحفظ مسودته ← تنشيط التصنيف بعقده الحالي ← عرض
المقترحات الملائمة لمجلس الاجتماع وتاريخه أثناء تحضير جدول الأعمال. المقترح
قراءة مشتقة لا سجل موضوع جديد؛ لا معرف يطلب من المستخدم ولا توليد مكرر عند
تحديث الصفحة. اعتماد المقترح ورفع مرفقاته رحلة لاحقة مستقلة؛ لا زر اعتماد وهمي.

المستهلكون: محرر تصنيفات الموضوعات، نموذج المتطلبات، أمر حفظ الحزمة، قراءة
تفاصيل الاجتماع، لوحة جدول الأعمال. API get_meeting_detail يبقى بنفس التوقيع
مع حقل اختياري إضافي. المسارات والبنود ومحرك الموضوعات V1 والدعوات لا تتغير.

العقود والجداول: ملفات إعداد التصنيف، سياسات توقيته، الحزمة والنوع وربط المسار،
المجالس، meetings. قراءة المقترحات داخل وحدة الحوكمة؛ وحدة الاجتماعات تستدعيها
بمنحة مسجلة محدودة. الصلاحية agenda.manage في سياق المجلس؛ القراء والمجالس
الأخرى لا يكتسبون صلاحية من مجرد الاطلاع على اجتماع. يظل فحص قراءة الاجتماع
القديم سابقًا على المقترحات. الاجتماعات غير القابلة للتحضير لا تتلقى المقترحات.

الحفظ ذري مع إيصال التكرار الموجود؛ أي رفض يعيد المعاملة. بيانات التصنيفات
القديمة اليدوية أو غير المجدولة باقية، ولا تدخل المقترحات. لا تعديل مسودات المستخدم
ولا تشغيل seed أو حذف بيانات أو نشر إنتاج. ترحيل أمامي جديد للتطوير فقط.

الاختبارات أولًا: غياب خيار المقترح قبل الجدولة؛ ظهوره بعدها ومسحه عند إلغائها؛
رفض إعداد آلي غير مجدول في الخادم؛ اقتراح نافذ واحد داخل نافذته فقط، خارج
النافذة/النطاق/مدة الدورية صفر؛ لا تكرار ولا كتابة موضوعات؛ منع غير المخول؛ سلامة
تفاصيل الاجتماع القديمة. عرض ضيق ومكتبي، lint وtypecheck والعقود وحوكمة التطوير.

## نتيجة التحقق

- أضيف ترحيل التطوير 20261008020300 فقط؛ لا تغيير لإنتاج أو حذف بيانات.
- اختبارات الواجهة: 15 نجاحًا، تشمل إخفاء الخيار ومسحه عند إلغاء الجدولة
  وإظهار المقترحات منفصلة عن البنود المعتمدة. typecheck وlint للملفات المتأثرة ناجحان.
- قاعدة البيانات: 56 = 29، 72 = 59، 55 = 17، 52 = 19، 57 = 14،
  58 = 7، 13 = 14. إصلاح نطاق بيانات اختبار 55 يحصر إعداداته واستعلاماته
  في مؤسسة الاختبار بدل جميع بيانات التطوير؛ لا تغيير في عقد التنشيط نفسه.
- العقود 79 نجاحًا، حوكمة التطوير وترميز الوثائق ناجحان. اختبار متصفح فعلي
  لإعداد التصنيف وحفظه بعرض مكتبي وضيق ناجح؛ المؤسسات والحسابات المستخدمة معزولة.
- المقترحات مشتقة أثناء قراءة تفاصيل الاجتماع، لا تحتاج عاملًا مجدولًا أو
  توليد سجل موضوع مسبقًا، ولا تنشئ اجتماعات دورية أخرى. تكرار القراءة مستقر.

حد التسليم: عرض المقترحات وإعدادها مكتمل ضمن هذا النطاق. اعتماد المقترح كموضوع
فعلي ورفع مرفقاته وربطه بمحرك V2 ليست إجراءات منشورة هنا، ولا تُعرض أزرار توهم
بإتاحتها. قائمة مسودات التصنيفات وإعادة فتحها وتنشيطها ما زالت مهمة منفصلة؛
المقترحات لا تستخدم المسودات. اختبار المقترحات الفعلية اعتمد بيانات نافذة
معزولة داخل معاملة متراجعة، ولم يُنشّط مسودات المستخدم.
