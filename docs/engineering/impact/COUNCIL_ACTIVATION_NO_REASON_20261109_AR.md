# خريطة أثر: تفعيل المجلس بلا سبب، إضافة أعضاء دفعة، المحضر الرسمي داخل الاجتماع المكتمل

1. **تفعيل المجلس بلا سبب (قرار المالك 9 نوفمبر):** السبب يُطلب للتعطيل والأرشفة فقط.
   `change_council_status` صار يقبل تفعيلاً بلا سبب ويحفظ سبباً معيارياً «تفعيل المجلس» في سجل الحالات
   والتدقيق (ترحيل `20261109030000`). نافذة التفعيل تسأل التأكيد فقط. اختبار `27` عُدّل وأُضيف له تأكيدان.
2. **إضافة أعضاء متعددين:** نافذة العضو صارت قائمة اختيار متعدد (بحث، شارات المحددين، زر «إضافة N أعضاء»)
   بدور وفترة واحدة. التنفيذ عقد `admin_add_council_member` لكل شخص بالتتابع، ومن تعذّر يُذكر اسمه وسببه ويبقى من
   أُضيف؛ لا عقد دفعي ذري بعد.
3. **غياب اجتماعات الدراسات العليا:** ليست مفقودة؛ المجلس نشط لكن بلا خطة اجتماعات ولا اجتماع واحد في القاعدة
   (أُنشئ دون «إنشاء خطة اجتماعات»). تُنشأ الخطة من تعديل المجلس.
4. **المحضر داخل الاجتماع المكتمل:** صفحة الاجتماع المكتمل/المؤرشف تعرض «عرض المحضر المعتمد» و«تنزيل المحضر الرسمي».
5. **تصميم المحضر الرسمي (PDF):** أُعيد بناؤه كوثيقة رسمية: ترويسة الجامعة، عنوان المحضر، جدول بيانات الاجتماع
   (الرقم، المجلس، التاريخ، الوقت «من… إلى…»، المكان، الجلسة والعام، النصاب)، ملاحظات الانعقاد (نصاب ناقص، خارج الدورة)،
   جدول الحضور الكامل (حاضر/غائب/معتذر)، جدول الأعمال بالملخص والنتيجة والقرار ورقمه والتكليفات، جدول المصادقة
   بالتوقيعات وتواريخها، رمز التحقق. حُذف: الجمل الحشو («تمت مناقشة البند وإثبات نتيجته…»)، والبطاقات الملونة، وصندوق
   البصمة الداكن. الحضور والنصاب من `get_meeting_session_detail` وعند عدم الصلاحية يرجع لقائمة الموقعين.
   رُسم على بيانات `MTG-2026-000007` الحقيقية وفُحص بصرياً (صفحتان).
- **الاختبارات:** اختبارات الاجتماعات والمجالس ومسار API ناجحة؛ DB `13` `14` `27` `28` ناجحة.
- **المتبقي:** إعادة تصميم عرض المجالس وربط اجتماعاتها وإعداداتها.
