# خريطة أثر بيئة التطوير البعيدة

## الثابت الوظيفي

- لا تستخدم واجهة التطوير قاعدة بيانات الإنتاج أو مفاتيحها أو مجلدات تخزينها.
- يبقى `qarar.prideidea.com` موجهاً إلى حزمة الإنتاج المبنية.
- يوجه `devqarar.prideidea.com` فقط إلى خدمة Next.js التطويرية.
- إعادة تشغيل بيئة التطوير لا توقف خدمات الإنتاج.

## المستهلكون والأسطح المتأثرة

- Docker Compose الخاص بـ Supabase: نسخة تطوير مستقلة ومنافذ مستقلة.
- Dashboard: ملفات المصدر مربوطة مباشرة وتشغّل `next dev`.
- Nginx المشترك: مضيف افتراضي جديد فقط، دون تعديل مضيف الإنتاج.
- البيانات: مجلدا Docker مستقلان لقاعدة التطوير والتخزين.

## الحالات والفشل والتراجع

- قبل: النطاق الجديد يصل إلى المضيف الافتراضي ولا يشغّل قرار.
- بعد: النطاق يصل إلى Dashboard التطوير، والواجهة تتحدث إلى Supabase التطوير فقط.
- الفشل: يبقى الإنتاج دون تغيير، ويعاد النطاق الجديد إلى استجابة صيانة/عدم توفر.
- التراجع: إيقاف حاويات `qarar-dev-*` وحذف مضيف Nginx الجديد، دون لمس حاويات أو بيانات الإنتاج.

## التحقق

- فحص تركيب Docker Compose وNginx قبل إعادة التشغيل.
- التحقق من صحة `/api/health` على نطاقي التطوير والإنتاج.
- إثبات اختلاف حاوية وقاعدة ومجلد تخزين التطوير عن الإنتاج.
- اختبار ظهور تعديل واجهة تجريبي عبر Hot Reload دون إعادة بناء صورة.
