# إضافة نوع الوحدة داخل نافذة الإنشاء

- الرحلة: تسمية الوحدة ← اختيار النوع أو إضافته في موضعه ← حفظ الوحدة ← استخدامها كنطاق للمجلس.
- الثابت: لا إغلاق لنافذة الوحدة ولا فقد الاسم أو الجهة الأم أثناء إضافة نوع. لا نموذج HTML متداخل. لا إنشاء للوحدة عند ضغط Enter في حقل نوع جديد.
- العقود: إعادة استخدام admin_create_organizational_unit_type_v2 عبر API المجالس بلا تغيير؛ الصلاحية governance.unit_types.manage مستقلة عن governance.units.manage. تحديث قوائم النافذة والصفحة فور نجاح إضافة النوع واختياره تلقائيًا.
- التأثير: OrganizationalUnitDialog وOrganizationalUnitsWorkspace ومحرر نوع الوحدة فقط؛ نفس الجداول والأقفال والتدقيق بالخادم. لا ترحيل ولا تحديث بيانات قديمة، ولا مهام أو حالات جديدة.
- الفشل: يبقى المحرر في النافذة مع رسالة عربية ومدخلاته محفوظة. أثناء حفظ النوع تمنع عمليات حفظ الوحدة والإغلاق والنقر المكرر. الرجوع بالكود فقط.
- الاختبارات قبل التنفيذ: بقاء اسم الوحدة والجهة الأم، اختيار النوع الجديد، خطأ موضعي وإعادة المحاولة، عدم إنشاء الوحدة عند Enter، إخفاء الإضافة عن غير المخول. إعادة اختبار إنشاء الوحدة والمجلس المجاور والمتصفح المكتبي والضيق.
- سؤال العمليات الأخرى: هذه الحزمة لا تضيف تعديلًا أو تعطيلًا أو حذفًا لأن الطلب يستفسر عن سبب غيابها؛ الواجهة السابقة لم تشمل إدارة دورة الحياة. يوجد عقد V1 لتحديث الوحدات وحالات active/inactive/archived، لكنه مستهلك أيضًا في اللوائح. أي إتاحته تتطلب مراجعة تبعية المجالس والوحدات الفرعية ومنع دوائر الهيكل والحذف المؤثر، ولا يكفي وصل زر بالعقد الحالي.

## نتائج التحقق

- اختبارا السلوك الجديد فشلا قبل التنفيذ لغياب زر الإضافة داخل النافذة.
- نجحت 18 حالة واجهة/API بعد التنفيذ، تشمل حفظ الاسم والجهة الأم، اختيار النوع تلقائيًا، الفشل داخل المحرر، منع الإغلاق والإرسال أثناء الحفظ، رفض العرض لغير المخول، وبدء التهيئة دون أنواع مسبقة. تم تصحيح تنظيف mocks لمنع تسرب طلب معلق بين الاختبارات.
- Typecheck وESLint للملفات المتأثرة وtest:development-governance وdiff --check ناجحة.
- رحلة المتصفح الفعلية على نطاق التطوير نجحت على الكمبيوتر و390px: إضافة النوع داخل نافذة الوحدة، إنشاء الوحدة ثم استخدامها كنطاق مجلس، خطأ تكرار موضعي، وإضافة نوع في الهاتف عبر Enter دون إنشاء الوحدة أو فقد الاسم. لا أخطاء runtime أو استجابات 5xx. حساب الاختبار مستقل ومعطل بعد الفحص.
- لم يتغير أي عقد أو قاعدة بيانات أو بيانات مستخدمين أو إنتاج في هذه الخطوة. إدارة تعديل/تعطيل/حذف الوحدات ما زالت غير منفذة.
