# هوية تصنيفات الموضوعات والتسمية الآلية

## قبل التنفيذ

واجهة نوع الموضوع تطلب code رغم الاتفاق، وتعرض إحصاءات صفرية ثابتة ومعاينة داكنة
وألوانًا محلية تختلف عن متغيرات الهوية. المسارات ومكتبة البنود تملكان لوحات ألوان
مستقلة. اسم القائمة مؤقت «نموذج الحوكمة الجديد».

## الرحلة والثوابت

اختيار المجال وكتابة الاسم ← اختيار المسار وسياسات المجالس ← التوقيت ← ملخص وحفظ.
لا حقل أو رمز مؤقت يولده العميل. UUID يبقى داخليًا؛ المرجع TYP-YEAR-SEQUENCE
تولده دالة العداد الموجودة، والرمز التقني مشتق منه بحروف صغيرة وفواصل سفلية.
تعديل الاسم/المجال يحافظ على المرجع والرمز. المسودة تبقى مسودة؛ لا تفعيل ضمني.
التوقيت غير المكتمل لا يقدم كإعداد عامل أو يسمح بحفظه على أنه مكتمل.

## الأثر والعقود

Route Handler /api/admin/governance-model يرفض رمز نوع الموضوع اليدوي؛ الطلب
بدون topic_type.code. غلاف قاعدة البيانات الحالي يدعم الغياب ويطبع إيصال التكرار
على الطلب الأصلي. يبقى قبول الرموز للعقود الداخلية السابقة للتوافق دون تغيير
السجلات القديمة. مشغل قبل إدخال topic_types_v2 يستبدل قيمة محجوزة داخلية بالرمز
المشتق من reference_number بعد احتساب default؛ لا عداد جديد أو max+1.
تعديل المسودة بدون code يقرأ الرمز القديم في المؤسسة وصاحب الحزمة فقط.
الفشل يتراجع عن كامل الحفظ والعداد والإيصال؛ التكرار بنفس المفتاح يعيد المرجع نفسه،
والمحتوى المختلف يرفض. الصلاحية governance.model.edit والعزل كما هما.
لا تغييرات على الاجتماعات أو التنشيط أو المحاضر أو المهام أو ملفات المستخدمين.

## الواجهات

عنوان وتنقل مشترك للوائح والمسارات والتصنيفات باستخدام متغيرات globals.css
المعتمدة، لوحات بيضاء وخلفيات خفيفة وأزرق أساسي، برتقالي للهوية لا كحالة نجاح.
ألوان الحالة دلالية فقط. حذف الإحصاءات الوهمية والبحث غير الموصول بدل ادعاء عمله.
معاينة مختصرة دون رمز قبل الحفظ؛ إظهار مرجع نوع الموضوع الحقيقي بعده.
تبسيط الخطوات من خمس إلى أربع بحذف خطوة القرار المعلوماتية وإبقاء السياسات
بجوار المسار. قائمة التصنيفات المحفوظة وعملياتها مرحلة مستقلة لم تنفذ بهذه الحزمة.

## الاختبارات والإصدار

اختبارات قبل التنفيذ: غياب حقل code والطلب دون code، توليد TYP والاشتقاق المطابق،
التكرار/التعارض، تعديل ثابت الهوية، صلاحية ممنوعة ومؤسسة أخرى، توافق عقد قديم.
فحص متصفح معزول للحفظ الحقيقي، الحقل الغائب والمرجع المخزن، فشل وحفظ المدخلات،
وعرض 1440/390 للتصنيفات والمسارات والبنود. typecheck/lint والعقود وحوكمة التطوير.
ترحيل أمامي جديد على التطوير فقط؛ لا تغيير للإنتاج أو زرع بيانات. الرجوع بالواجهة
السابقة ممكن لأن العقد القديم يبقى مقبولًا داخليًا، دون محو السجلات الجديدة.

## نتيجة التحقق على التطوير

- ترحيل 20261008019000 مطبق على قاعدة التطوير فقط مع بصمة سجل الترحيلات.
- 42 اختبار قاعدة بيانات للمسارات والسياسات والهوية، منها صلاحية التحرير والعزل
  بين المؤسسات، و14 اختبار تسجيل معماري: ناجحة.
- 31 اختبار واجهة وعقد HTTP للتصنيفات والمسارات ومكتبة اللوائح: ناجحة.
- 79 اختبار عقود الحوكمة، typecheck وlint الموجّه وحوكمة التطوير: ناجحة.
- 38 اختبارًا مجاورًا لعقد المسودة ونموذج القراءة وخيارات التأليف: ناجحة.
  اختبار المسودة القديم كان يحصي سجلات جميع المؤسسات ويفترض قاعدة فارغة؛
  قُيّدت استعلاماته بمؤسسة الاختبار دون حذف البيانات أو تخفيف التأكيدات.
- اختبارا متصفح معزولان على devqarar: حفظ تصنيف حقيقي دون code، مرجع مخزن مطابق،
  سياسات مستقلة، وفشل وإعادة محاولة؛ وتأليف البنود وتنشيطها وتعطيلها واستعادتها.
- فحص بصري لعرض الكمبيوتر والجوال؛ إزالة تداخل شريط الخطوات مع الحقول على الجوال.
- لم تتغير بيانات المستخدمين الحالية أو الإنتاج. حسابا الاختبار المعزولان معطلان
  بعد الاختبار، مع حفظ الأثر التدقيقي.

المتبقي صراحة: قائمة التصنيفات المحفوظة وتعديلها ودورة تنشيطها، والتوقيت الدوري
والموسمي. لا تمثل هذه الحزمة اكتمال إدارة تصنيفات الموضوعات كلها.
