# خريطة أثر: الإجراء التصحيحي الرسمي للموضوع وقراراته ومحاضره

## رحلة المستخدم والثابت التجاري

- يفتح رئيس المجلس الذي عنده الموضوع طلب تصحيح شكلي واحداً، ويحدد كل موضع وقيمته
  الحالية والصحيحة وسببه. لا يقبل تغيير المضمون أو الأصوات أو نتيجة التصويت.
- يمر الطلب على المجالس السابقة واحداً واحداً بلا تجاوز. رئيس المحطة النشطة وحده
  يوافق أو يرفض بسبب. الموافقة تنشئ نسخة مصححة لوثيقة مجلسه إن شملها الطلب، ثم تنقل
  الطلب للمحطة التالية. الرفض يعيده إلى فاتح الطلب؛ والسحب له قبل الاكتمال.
- الأصل لا يتغير ولا يُحذف. القراءة الرسمية تعرض أحدث نسخة مع شارة التصحيح ورابط
  الأصل، ويحتفظ المحضر المصحح بتوقيعي الرئيس والمقرر وبسجل المواضع قبل/بعد.
- طوال الطلب النشط يبقى الموضوع في مكانه الذي فُتح منه، لكنه محجوز للتصحيح: لا إدراج
  جديد ولا تصويت ولا طلب ثانٍ. عند الاكتمال يعود للحالة والخطوة نفسهما ويكمل مساره.

## الخريطة التقنية والمستهلكون

- **الجداول الجديدة:** طلبات التصحيح، مواضع التصحيح، محطات المرور، نسخ الوثائق،
  وتوقيعات النسخة المصححة. كلها مؤسسية، إلحاقية للنسخ، وبمراجع بشرية من الخادم
  `COR-YYYY-NNNNNN`.
- **العقود:** فتح الطلب، قراءته، قرار المحطة، تعديل الطلب المرفوض، سحبه، توقيع النسخة،
  وقراءة أحدث نسخة لقرار/محضر. الواجهة في ملف الموضوع تعرض الحالة والمسار والإجراء
  السياقي عند موضعه.
- **الجداول المقروءة:** `topics`، مثيل وخطوات ودورات المسار، الاجتماعات والبنود،
  القرارات، المحاضر ومصادقاتها، العضويات والأدوار والمستخدمون.
- **الكتابة:** لا تعديل للأصوات أو جولات التصويت. نسخ القرار والمحضر إلحاقية. تعديل
  حقول الموضوع المسموح بها يتم فقط عند محطة المقدم وبعملية مضبوطة تحفظ لقطة الأصل.
- **المستهلكون:** تفاصيل الموضوع وملف PDF، سجل الاجتماع السابق، تفاصيل القرار والمحضر،
  أهلية جدول الأعمال، فتح التصويت، سجل النشاط والتدقيق، والإشعارات التشغيلية.

## الحالة والانتقالات

- قبل الفتح: موضوع في مرحلة مسار نشطة، لا طلب تصحيح مفتوح، وغير مدرج في اجتماع حي.
- الفتح: `traversing`، المحطة السابقة المباشرة `active`، ويحفظ الطلب لقطة موضع الموضوع
  وحالته وإصدار خطوة المسار للعودة وفحص التزامن.
- محطة فعالة → موافقة: تنشأ نسخة واحدة ذرّياً؛ تصبح المحطة `approved` وتفعل التالية،
  أو يصبح الطلب `completed` وتستعاد لقطة المسار.
- محطة فعالة → رفض: تصبح المحطة `rejected` والطلب `returned_to_opener`. لا تتقدم.
- طلب معاد → تعديل وإعادة إرسال أو `withdrawn`. الطلب المكتمل لا يعاد فتحه.
- أي إصدار متوقع قديم يرفض بـ`40001`. فشل إنشاء النسخة أو النقل يلغي المعاملة كلها.

## الصلاحيات والأخطاء

- الفتح لرئيس المجلس الحالي سياقياً؛ قرار المحطة لرئيس وحدتها الحالي لا لمدير النظام
  ولا لرئيس مجلس آخر. المقرر يوقع المحضر المصحح ولا يقرر المحطة.
- `corrections.read` قراءة حوكمة فقط، ولا تمنح أي انتقال.
- الواجهة تعرض انتظاراً ونجاحاً وخطأً عربياً عند الإجراء، وتشرح سبب تعطيله. تحتفظ
  السجلات بالسبب الداخلي ومعرف الطلب دون كشف SQL أو أسماء الحالات التقنية.

## البيانات القديمة والترحيل والرجوع

- لا تحويل للموضوعات أو القرارات أو المحاضر القديمة؛ تظهر بلا تصحيح حتى ينشأ طلب.
- الترحيلات أمامية فقط. النسخ لا تحذف عند إيقاف الواجهة. الرجوع يكون بتعطيل العقود
  الجديدة وترحيل تصحيحي، مع إبقاء السجل التاريخي قابلاً للقراءة.

## اختبارات الانحدار والقبول

- فشل أولي يثبت غياب الكيانات والعقود وحارسي الإدراج والتصويت.
- رحلة ثلاثة مجالس بالترتيب، نسخة قرار ومحضر لكل محطة ذات صلة، ثم العودة للخطوة نفسها.
- رفض محطة وإعادة الإرسال والسحب، ومنع التجاوز والرئيس الخطأ والعضو ومدير النظام.
- منع الإدراج والتصويت وطلب ثانٍ أثناء التصحيح، وعدم تغير الأصوات والنتائج.
- الأصل وأحدث نسخة وسجل قبل/بعد والتوقيعان، ومنع اعتمادين متزامنين من إنشاء نسختين.
- اختبار المرحلة السابقة (اكتشاف الموضوع) واللاحقة (إكمال المسار) إضافة إلى سطح المكتب
  والعرض الضيق، وفشل الخادم والتحقق والتعارض.
