# خريطة أثر واجهة إعداد أنواع الموضوعات V2

## الرحلة والثابت التجاري

- الرحلة: استعراض أنواع الموضوعات ثم إنشاء مسودة عبر خطوات: الهوية، القرار، مسار الحوكمة، التوقيت، المراجعة.
- الثابت: لا ترسل الواجهة معرفاً داخلياً أو رقماً مرجعياً أو حالة أو علم تفعيل. الحفظ المتاح حالياً يقتصر على المسودة ويستعمل الخيارات الصادرة من الخادم فقط.
- قبل: شاشة اللوائح القديمة تجمع وظائف كثيرة في مساحة واحدة وشريط تنقل فرعي.
- بعد: واجهة مستقلة خلف feature flag تقرأ خيارات الإعداد وتحفظ حزمة المسودة ذرياً، بلا تغيير لمسارات V1.
- الفشل: يظهر بجانب الإجراء أو الحقل، وتحفظ المدخلات المحلية، ولا يوجد فشل صامت.

## التأثير

- API والبيانات: تتصل الواجهة بعقد قراءة خيارات الإعداد وبأمر حفظ المسودة في `api_v2` عبر Route Handler محمي بالجلسة وCSRF. يعيد عقد القراءة التصنيفات الصالحة ونسخ المسارات الفعالة المتحقق منها، ولا تخترع الواجهة معرفات أو حالات.
- الحفظ: يعاد استخدام التصنيف المشترك بدلاً من إنشائه أو تغيير اسمه من مسودة موضوع، ويحفظ ربط المسار وسياسة الجدولة ذرياً مع الحزمة. فشل أي جزء يعيد المعاملة كلها.
- الصلاحيات: منح الإصدار المحدود دور `authenticated` تنفيذ عمليتي قراءة الخيارات وحفظ المسودة فقط. تبقى أوامر التحقق والإرسال وطلب التعديل والاعتماد والتفعيل محجوبة، وتتحقق عملية الحفظ من صلاحية `governance.regulations.manage` سياقياً. الصفحة لا تظهر إلا عند تفعيل العلم.
- الاستجابة: لا شريط جانبي فرعي؛ شبكة سطح المكتب تتحول إلى عمود واحد، ومؤشر الخطوات يصبح بطاقة تقدم مختصرة على الهاتف بدلاً من فرض تمرير أفقي. يظهر مسار الحوكمة أفقياً على الشاشات الواسعة ورأسياً على الهاتف.
- الوصول: عنوان وحيد، تسميات حقول، `aria-current` للخطوة، وحالة الأخطاء بـ`role=alert`.

## الاختبار والإصدار

- اختبار تفاعل للانتقال والتحقق ومنع تجاوز الحقول المطلوبة، وتحميل الخيارات، ونجاح الحفظ، وفشل الخادم وإعادة المحاولة ومنع الإرسال المزدوج.
- اختبار بنيوي لمؤشر الهاتف ومسار الحوكمة المتجاوب، مع منع اعتماد حد أدنى ثابت لعرض محرر الخطوات.
- typecheck وlint واختبارات الواجهة والبناء.
- لا نشر إنتاجي ولا إضافة للقائمة الرئيسية قبل اختبار الرحلة المتكاملة على staging. إصدار التأليف الحالي لا يفتح دورة المراجعة أو الاعتماد أو التفعيل.
