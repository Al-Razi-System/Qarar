# تحقق منح الصلاحيات وسحبها

## خريطة الأثر قبل التنفيذ

- الطلب: استكمال اختبار تعريفات الصلاحيات الـ61؛ الاختبارات السابقة غطت تعريفاتها وصلاحيتين فقط في رحلة المتصفح.
- الثابت: الطلب المعلق لا يمنح ولا يسحب؛ الاعتماد المستقل يطبق التغيير. السحب يلغي المنحة المحددة، ولا يلغي منحة أخرى مستقلة أو يغير الهوية.
- الرحلة: اختيار الصلاحيات ← طلب تغيير ← اعتماد مستقل ← قراءة المنح وتنفيذ بوابة الصلاحية ← طلب السحب واعتماده ← رفض البوابة.
- المستهلكون: واجهة الأدوار، `/api/admin/iam`، `admin_request_role_permissions_change` و`admin_review_iam_change`، `has_permission` و`actor_has_permission` و`assert_permission`.
- الجداول: permissions، roles، role_permissions، memberships، iam_change_requests، users؛ تهيئة المؤسسة تستعمل مشغلات الدليل القائمة. لا تعديل للعقود أو الترحيلات أو البيانات القديمة.
- الأدوار: مديران مستقلان للطلب والاعتماد؛ مستخدم عادي يحمل الدور؛ مستخدم آخر بلا منح. لا يستخدم مدير النظام لتمثيل صاحب الدور.
- الحالة: قبل الاعتماد تبقى المنح السابقة؛ بعده تطبق المجموعة المطلوبة. الاختبارات داخل معاملة قابلة للتراجع أو مؤسسة تطوير جديدة؛ لا تغيير لحسابات قائمة.
- يجب عدم الخلط بين اختبار محرك التفويض واختبار العملية التجارية. أسماء الصلاحيات التي لا يوجد لها مستهلك فعلي توثق، ولا تُعتبر مختبرة تشغيليًا لمجرد نجاح `has_permission`.
- الاختبار: لكل تعريف منح وسحب عبر عقود الاعتماد، رفض الاعتماد الذاتي، عزل الأعضاء، سياق المجلس/المؤسسة، تعطيل الدور وانتهاء العضوية. اختبار المتصفح يحدد جميع التعريفات ويسحبها ويقرأ النتيجة الفعلية.
- لا عطل محدد معلوم قبل التوسعة؛ هذه اختبارات استكشافية لتغطية ناقصة. أي عطل تكشفه يصبح حالة فاشلة قبل إصلاح السلوك بترحيل أمامي منفصل.
- خارج النطاق: دمج فروع المطور الآخر، إصلاح CI نيابة عنه، تغييرات التصميم، منح المستخدمين الحقيقيين، النشر على الإنتاج.

## تحديث الطلب: الحفظ المباشر لمسؤول النظام

- ألغى المستخدم اشتراط طلب واعتماد مستقل لمسؤول النظام. واجهة الأدوار تستعمل عقد حفظ جديدًا محصورًا في مسؤول نظام نشط داخل مؤسسته؛ مجرد `iam.permissions.manage` لا يمنح هذا التجاوز.
- مراجعة الأثر داخل الصفحة تأكيد محلي، وليست إرسال طلب. السبب اختياري؛ يسجل التدقيق الفاعل والمنح قبل وبعد.
- أمر ذري يقفل حد سلطة IAM ثم الدور؛ يقارن مجموعة المنح التي قرأها المستخدم بالمجموعة الحالية، ويمنع فقد تغييرات صفحة أخرى. إيصال بمعرف UUID يمنع إعادة الحفظ عند انقطاع الرد من تطبيق التغيير مرتين.
- العقود القديمة تبقى للتوافق. الحفظ المباشر يحسم طلبات استبدال صلاحيات الدور المعلقة بوصفها مرفوضة ومستبدلة بالحفظ المباشر، ويسجل معرفاتها؛ لا يمكن اعتماد طلب قديم فوق اختيارات جديدة. يتشارك إنشاء/اعتماد الطلب القديم والحفظ المباشر قفل سلطة IAM قبل قفل السجل.
- اختبار فاشل أولًا للعقد غير الموجود ولواجهة الحفظ؛ ثم اختبار مباشر لكل تعريف، السحب، التكرار والتعارض والمدير/غير المدير والمؤسسة الأخرى. لا تعديل لترحيل سبق تطبيقه.
# تحديث نتائج التحقق

اختبار قاعدة البيانات 93: 915 تأكيداً، و94: 379 تأكيداً، ناجحة على التطوير داخل معاملات rollback. هذا تحقق محرك التفويض للـ61 صلاحية، وليس إثبات تشغيل كل عملية عمل تحميها تلك الصلاحيات. اختبار المتصفح نجح في حفظ 61 صلاحية مباشرة دون طلب اعتماد ثم سحبها؛ رفض المستخدم غير الإداري وتحقق النطاق وانتهاء العضوية نجحا. اختبار طلبَي HTTP المتزامنين لم يكتمل بسبب timeout، فلا يُسجّل ناجحاً. حسابات الاختبار معزولة وتُحظر في finally. يلزم استكمال تزامن HTTP والرحلات الفعلية قبل وصف جميع الصلاحيات بأنها متحقّقة تشغيلياً.
