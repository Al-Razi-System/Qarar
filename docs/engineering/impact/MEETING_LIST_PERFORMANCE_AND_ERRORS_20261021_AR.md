# خريطة أثر أداء قائمة الاجتماعات وتشخيص أخطاء التحميل

التاريخ: 21 أكتوبر 2026

## الرحلة والثابت التجاري

- **الرحلة:** يفتح المستخدم «الاجتماعات والقرارات»، فتُحمّل قائمة الاجتماعات التي يحق له رؤيتها، ثم يختار اجتماعًا لعرض تفاصيله.
- **المشكلة المثبتة:** استعلام `search_meetings` يعيد اجتماعين للمستخدم الحالي خلال 5.8–7.9 ثوانٍ، وتلغيه مهلة قاعدة البيانات أحيانًا بالرمز `57014`. الواجهة تكرر الطلب عند التركيز وعودة التبويب، وقد تطلق طلبات متداخلة، ثم تعرض العبارة العامة «تعذر تنفيذ العملية».
- **الثابت:** تحسين الأداء لا يوسع نطاق القراءة. يبقى الاجتماع مرئيًا فقط لمسؤول النظام، أو منشئه، أو صاحب `meetings.read`/`meetings.manage` وفق نطاق الصلاحية أو تفويض فعّال.
- **قبل الإجراء:** طلب قائمة غير متزامن قد يتكرر، وفحص صلاحيات صفّي مكرر في استعلام العناصر والعدد.
- **الانتقال المسموح:** احتساب نطاق الوحدات المقروءة مرة واحدة داخل العقد نفسه، وبناء مجموعة النتائج والعدد من مرشح واحد؛ إلغاء طلب المتصفح الأقدم عند استبداله، وتحديث العودة فقط إذا أصبحت البيانات قديمة.
- **بعد الإجراء:** قائمة مطابقة وظيفيًا، طلب واحد فعّال، تحميل مستقل غير محجوب ببيانات السلاسل، وخطأ عربي مصنف مع إعادة محاولة.
- **الفشل/الرجوع:** فشل الاستعلام يبقي آخر قائمة ناجحة إن وجدت ولا يعرض أصفارًا على أنها نتيجة حقيقية. التراجع عن ترحيل الدالة يكون بترحيل أمامي آخر يعيد العقد السابق؛ لا تعديل رجعي لترحيل منفذ.

## المستهلكون والعقود والبيانات

- **المستهلكون:** `MeetingsWorkspace`، عميل `meetingRpc`، مسار `/api/admin/meetings`، وعقد `api_v1.search_meetings`.
- **الجداول:** قراءة فقط من الاجتماعات والمجالس والأنواع وبنود الجدول، ومن العضويات والأدوار والصلاحيات والتفويضات. لا كتابة ولا إصلاح بيانات.
- **العقد:** يبقى توقيع `search_meetings` وبنية `items/total/limit/offset` كما هي. يضاف تصنيف آمن للمهلة `QUERY_TIMEOUT` ولتعذر الخدمة، مع بقاء السبب الداخلي ومعرف التتبع في سجل الخادم.
- **الأدوار:** تُختبر قراءة صاحب صلاحية وحدة، ومنشئ اجتماع بلا صلاحية قراءة، ومسؤول النظام، ومنع مستخدم المؤسسة الأخرى.
- **الحالات:** تحميل أولي، نجاح، قائمة فارغة حقيقية، تحديث خلفي، إلغاء طلب قديم، انقطاع متصفح، مهلة قاعدة، انتهاء جلسة، وفشل خادم.
- **السجلات القديمة:** لا تتغير، ولا يلزم إصلاح أو بذر.

## الاختبارات والقياس

1. اختبار قاعدة يحمي تطابق العناصر والعدد وعزل المؤسسة، ويثبت أن تنفيذ الخطة لا يستدعي `has_permission` لكل صف.
2. اختبار المسار يترجم `57014` إلى مهلة عربية وحالة 503 دون كشف نص PostgreSQL.
3. اختبار العميل يميز عدم الاتصال والمهلة واستجابة الخادم، ويحترم `AbortSignal` لإلغاء الطلب المستبدل.
4. اختبار الواجهة يثبت وجود إعادة المحاولة وعدم تحويل الفشل إلى قائمة فارغة.
5. قياس الحساب نفسه قبل/بعد، مع هدف أقل من 500 مللي ثانية محليًا للقائمة الحالية.
6. تشغيل اختبارات الاجتماعات المركزة، وفحص الأنواع وlint والبناء عند الحاجة، ثم `npm run test:development-governance`.
