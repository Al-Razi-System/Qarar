# خريطة أثر: إرفاق دليل المهمة دون وصف

## الرحلة والثابت

- الرحلة: المنفّذ يفتح مهمته، يرفق دليلاً، ثم يسلّم الإنجاز إلى المتابع للتحقق.
- الثابت: وصف الدليل اختياري كما تعرضه الواجهة، ولا يجوز أن يمنع غيابه تسجيل ملف صالح.
- لا تتغير قاعدة أن المهمة التي تتطلب دليلاً لا تُسلّم قبل وجود دليل مسجل.

## الأثر

- المتصل: `POST /api/admin/tasks/evidence` والعقد `api_v2.add_task_evidence_v2`.
- المستهلكون: شاشة «مهامي» وتفاصيل المهمة، ثم عقد تسليم الإنجاز.
- الجداول: `qarar_execution.action_evidence` و`storage.objects`.
- الأدوار: منفّذ المهمة فقط يضيف الدليل؛ صلاحيات المتابع والمتحقق لا تتغير.
- السجلات القديمة: لا تحتاج إصلاحاً؛ الخلل يمنع إنشاء السجل أصلاً.

## الحالة والانتقال

- قبل الإجراء: المهمة `new` أو `in_progress` ولا يوجد دليل مسجل.
- الإجراء المسموح: رفع ملف صالح وتسجيله بوصف مكتوب أو فارغ.
- بعده: يبقى وضع المهمة كما هو، ويضاف الدليل ويصبح التسليم متاحاً إن استوفت بقية الشروط.
- الفشل: يُحذف الملف المرفوع إذا فشل تسجيله، وتظهر رسالة عربية عند موضع الإرفاق.

## السبب والإصلاح

- العمود `description` غير قابل لـ`NULL`، بينما الدالة حولت الوصف الفارغ إلى `NULL` رغم أن الواجهة تسميه اختيارياً.
- ترحيل أمامي يعيد تعريف الدالة لتحفظ الوصف الفارغ كسلسلة فارغة، مع إبقاء حد 500 حرف.

## الاختبارات

- إعادة إنتاج: إرفاق ملف موجود في المخزن مع `p_description = null`.
- المرحلة السابقة: تحديث تقدم المهمة.
- المرحلة التالية: تسليمها بعد تسجيل الدليل، ثم اعتمادها إلى 100% (مغطاة في اختبار رحلة المهام نفسه).
- الصلاحيات والعزل وبقية حالات الدليل تبقى ضمن `106_execution_tasks_test.sql`.
