# المستوى الحوكمي المشتق

المجلس الجديد يستمد تصنيفه من نوع الوحدة التنظيمية المرتبطة، وبدون وحدة يستمد نطاق المؤسسة. لا يُطلب تصنيف ثان من المستخدم. تحتفظ العقود السابقة بحقل governance_class_id كمرجع توافق للمسارات والسجلات التاريخية؛ لا نحذف المراجع التي تستهلكها topics ومسارات v1/v2 والجاهزية وواجهات البحث.

الأثر: مشغل core على governance_units عند إنشاء/تحديث مجلس بلا تصنيف، يستدعي وظيفة governance داخلية لضمان التصنيف. أنواع كلية وقسم وجامعة تستخدم أصنافها القياسية القائمة إن وجدت؛ النوع المخصص يولد صنفاً مرتبطاً بمعرف النوع الثابت، بمستوى other ولا ندعي أنه كلية أو جامعة. تغيير اسم النوع لا يغير معرف الصنف. النطاق المؤسسي صنف مستقل؛ استهداف مجلس الجامعة أو الأمناء تحديداً يبقى عبر هوية المجلس في المسار لا عبر اسم المستوى وحده.

الصلاحيات: الوظيفة الداخلية ليست API عامة، تنفذ تحت مالك governance ضمن نفس المنظمة، واستدعاؤها محصور بـcore. لا تعديل لعضويات أو أدوار المستخدمين. الإنشاء الذري يتراجع عند فشل اشتقاق التصنيف. المراجع التاريخية المحددة مسبقاً لا تعاد كتابتها لتفادي كسر المسارات الجارية. إعادة التصنيف التاريخي غير المتوافق تتطلب ترحيلاً منفصلاً مدققاً.

الاختبارات: مجلس مرتبط بقسم يتلقى تصنيف قسم دون حقل يدوي، مجلس مؤسسي يتلقى صنف المؤسسة، حفظ الصنف التاريخي، حدود المنظمة والصلاحيات، العقود السابقة للمسارات والجاهزية. تغيير نوع الوحدة المستخدمة يجب أن يمنع تغيير المستوى ضمنياً قبل مراجعة أثر المسارات (ليس مجرد تعديل اسم).

التحقق: 23 حالة عقد اجتازت الاختبار، وعقد حل المجالس التنظيمي السابق ما زال ناجحاً. تغيير نوع وحدة مرتبطة بمجالس ممنوع برسالة عربية؛ تعديل الاسم لا يغير نوعها. الوظائف الداخلية مسجلة ومقيدة بالملاك والصلاحيات ولا تعرض للعميل.
