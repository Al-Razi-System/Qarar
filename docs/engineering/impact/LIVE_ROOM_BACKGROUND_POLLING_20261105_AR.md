# خريطة أثر إيقاف قراءات الغرفة في التبويبات المخفية

## الرحلة والثابت

- الرحلة: فتح الغرفة الحية ← الانتقال إلى تبويب آخر ← العودة إلى الغرفة.
- الثابت: التبويب الظاهر يتلقى تحديثات الغرفة والتصويت كما هو، والتبويب المخفي لا
  يرسل حزم قراءة دورية ثقيلة لا يراها المستخدم. عند عودته للظهور يقرأ الحالة
  الحالية فوراً قبل جدولة القراءة الاحتياطية التالية.
- لا تتغير حالات الاجتماع أو التصويت أو الصلاحيات أو عقود RPC، ولا تُنفذ كتابة.

## خريطة التأثير

- المستهلكان: `LiveMeetingRoom` ومؤقت قراءة حالة البث الاحتياطية في
  `useMeetingBroadcast`.
- العقود: تفاصيل الجلسة والاجتماع والتصويت والقرارات والمرفقات والمؤقتات والإحالات
  والتكليفات تبقى كما هي.
- الفشل: إذا فشلت قراءة العودة، تبقى رسالة الخطأ المحلية وإعادة المحاولة الحالية؛
  لا تعتمد الشاشة حالة قديمة لتنفيذ تغيير.
- الأدوار: السلوك واحد للرئيس والمقرر والعضو، ولا يوسّع صلاحية.
- البيانات والترحيلات: لا تغيير.

## اختبار الانحدار

- تبويب مخفي لا يبدأ حزمة القراءة الدورية.
- تبويب مخفي لا يواصل قراءة حالة البث كل ثانيتين عند انقطاع قناة الأحداث.
- عند تحوله إلى ظاهر تبدأ حزمة واحدة فوراً.
- الاختبارات الحالية تحمي منع تداخل الدفعات، وعدم ضياع إشارة أثناء طلب قائم،
  واستمرار تحديث التصويت والمناقشة.
