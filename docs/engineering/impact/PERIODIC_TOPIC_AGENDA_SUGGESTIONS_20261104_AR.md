# خريطة أثر ظهور تصنيفات الموضوعات الدورية في مقترحات الاجتماعات

## تعريف التغيير

- **المشكلة المثبتة:** محرك قاعدة البيانات يعيد التصنيفات الدورية المستحقة في `scheduled_suggestions`، لكن صفحة رحلة الاجتماع المباشرة لا تعرض الحقل. كان العرض موجودًا فقط في لوحة الإدارة القديمة، لذلك تختفي البيانات الصحيحة عند فتح رابط الاجتماع.
- **القاعدة التجارية:** التصنيف المنشور والمفعّل، ذو نمط `automatic_agenda` وجدولة نافذة، يظهر اقتراحًا مشتقًا في اجتماع المجلس المطابق عندما تتقاطع دورة الاجتماع مع نافذة استحقاق التصنيف. الاقتراح ليس موضوعًا ولا بندًا معتمدًا، ولا ينشئ أثرًا جانبيًا أو نسخة مكررة.
- **السلوك الحالي المثبت:** التصنيف الفعلي «اعتماد برنامج أكاديمي» مفعّل ومتاح لمجلس القسم، وتعيده الدالة وتفاصيل اجتماع مجلس قسم إدارة الأعمال لدورة ديسمبر. صفحة `/admin/meetings/[id]` تهمل عرضه.
- **السلوك المتوقع:** صفحة رحلة الاجتماع تعرض نفس قائمة المقترحات التي تعيدها تفاصيل الاجتماع عندما يملك المستخدم `agenda.manage`. لا تظهر لمجلس أو دور غير مطابق، ولا تتحول تلقائيًا إلى بند.
- **خارج النطاق:** إنشاء موضوع تلقائي، اعتماد الاقتراح كبند دون مراجعة، أو تغيير تعريفات التصنيف وجدولته.

## خريطة الرحلة

- **المرحلة السابقة:** نشر تصنيف موضوع مفعّل بجدولة دورية ونطاق ومسار يبدأ بالمجلس المعني.
- **المرحلة المعدلة:** قراءة تفاصيل اجتماع في الإعداد وعرض المقترحات الدورية المستحقة.
- **المرحلة التالية:** يراجع رئيس المجلس المقترح، ثم ينشئ/يستكمل الموضوع وفق متطلباته قبل إدراجه؛ لا يتحول الاقتراح إلى بند تلقائيًا.
- **الحالة قبل العملية:** اجتماع `draft` أو `scheduled`، بيوم مؤكد أو نافذة دورة، وتصنيف `effective` و`automatic_agenda`.
- **شروط السماح:** صلاحية `agenda.manage` في سياق المجلس، مجلس فعّال، تصنيف ونسخة وحزمة وجدولة وربط مسار نافذة، ونطاق أصل يسمح بالمجلس.
- **الحالة بعد النجاح:** قراءة مستقرة تتضمن اقتراحًا واحدًا لكل نسخة تصنيف مستحقة.
- **الفشل أو التراجع:** تعاد قائمة فارغة خارج النطاق/الفترة؛ أخطاء العقود تحفظ سببها الداخلي ولا تنشئ بيانات جزئية.

## خريطة التأثير

- **الواجهات:** صفحة إدارة الاجتماع، بطاقة/قسم المقترحات المجدولة، وعدّاد المقترحات.
- **API/RPC:** لا تغيير؛ `api_v1.get_meeting_detail` يعيد الحقل الصحيح بالفعل.
- **البيانات:** `qarar_meetings.meetings`، `topic_types_v2`، `topic_type_versions_v2`، `governance_bundles_v2`، `topic_type_authoring_profiles_v2`، `topic_schedule_policies_v2`، `topic_type_workflow_bindings_v2`، و`workflow_template_steps`.
- **المشغلات والمهام:** لا تغيير ولا إنشاء مجدول؛ الاقتراح مشتق عند القراءة.
- **التدقيق:** لا حدث تدقيق للقراءة؛ إنشاء الموضوع أو إدراجه يبقي عقوده الحالية.
- **الأدوار:** مدير جدول أعمال المجلس يرى المقترحات؛ بقية الأدوار لا تكتشفها.
- **المستهلكون:** واجهة الاجتماعات واختبارات عقد تفاصيل الاجتماع. عقد `scheduled_agenda_suggestions_v2(uuid,date)` يبقى دون كسر.
- **البيانات القديمة:** لا إصلاح بيانات ولا ترحيل مطلوبان؛ الخلل في مستهلك الواجهة فقط.

## خطة الاختبار

- اختبار يفشل قبل الإصلاح: صفحة رحلة الاجتماع تتلقى `scheduled_suggestions` ولا تعرض التصنيف المستحق.
- واجهة بلا اقتراحات لا تعرض بطاقة مضللة، ومع اقتراح تعرض العدد والفترة والمتطلبات باستخدام رموز التصميم.
- اختبارات قاعدة البيانات الحالية تحمي المجلس والنطاق والصلاحية وعدم إنشاء بند تلقائيًا.
- اختبارات المرحلة السابقة (حفظ/نشر متطلبات التصنيف) واللاحقة (إدارة جدول الأعمال) تبقى ناجحة.

## خطة الإصدار

- لا ترحيل ولا تغيير عقد؛ دفعة واجهة قابلة للرجوع بإزالة مكوّن العرض فقط.
- التحقق على اجتماع مجلس قسم فعلي، مع فحص العرض المكتبي والضيق.
