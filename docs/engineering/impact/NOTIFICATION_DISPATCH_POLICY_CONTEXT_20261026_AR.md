# استعادة سياسة القناة والقالب في سياق إرسال الإشعارات — 26 أكتوبر 2026

## خريطة الأثر قبل التغيير

### رحلة المستخدم والثابت التجاري

- يحفظ مسؤول النظام تشغيل قناة واتساب وحالة كل قالب ونصه المخصص من صفحة الإعدادات.
- عند تجهيز عامل الإرسال لرسالة، يجب أن يقرأ السياسة المحفوظة للمؤسسة نفسها قبل
  الاتصال بالمزود.
- إيقاف القناة أو القالب يمنع الإرسال الجديد، والتخصيص الآمن يصل إلى منشئ الرسالة.
- لا تتغير حالة الاجتماع أو التكليف إذا تعذر الإشعار، ولا يُكشف رقم الهاتف للمتصفح.

### السبب الجذري

قاعدة تطوير `devqarar` تحتوي جدولَي الإعدادات ودالة السياق الأساسية، لكن الدالة العامة
`qarar_governance.get_notification_dispatch_context(uuid, uuid)` فقدت طبقة السياسة
وأصبحت تطابق الدالة الأساسية. لذلك تُحفظ الإعدادات في الواجهة، بينما لا يعيد عقد
التجهيز `channel_enabled` أو `event_enabled` أو تخصيص القالب.

### المتصلون والمستهلكون والعقود

- المستهلك: عامل إشعارات واتساب المنفصل.
- عقد الخدمة: `api_v1.service_get_notification_dispatch_context(uuid, uuid)`.
- التنفيذ: `qarar_governance.get_notification_dispatch_context(uuid, uuid)`، ويستدعي
  `get_notification_dispatch_context_base(uuid, uuid)`.
- الجداول المقروءة: `notification_settings` و`notification_template_settings`، إضافة
  إلى جداول سياق المستلم التي تقرؤها الدالة الأساسية.
- لا يتغير توقيع API ولا شكل الحقول القائمة؛ تُستعاد الحقول الخمسة المتفق عليها فقط.

### الحالة والانتقال والفشل

- قبل الإجراء: حدث إشعار مستأجر للعامل بحالة `processing` ورمز قفل صالح.
- الإجراء المسموح: قراءة سياق الحدث والمستلم وسياسة المؤسسة والقالب دون تعديل الحالة.
- بعد النجاح: يعود السياق الكامل مع سياسة القناة والقالب؛ يكمل العامل أو يتخطى الإرسال.
- عند فشل التحقق من الإيجار أو المؤسسة: تفشل القراءة كما في العقد الأساسي، ولا تتغير
  حالة الحدث أو التسليم.
- التراجع: الترحيل أمامي ويستبدل جسم الدالة فقط؛ لا يغير بيانات أو حالات جارية.

### الصلاحيات والبيانات القديمة

- يبقى العقد متاحًا لـ`service_role` فقط، والتنفيذ الداخلي لـ`qarar_api_executor` فقط.
- لا وصول جديد للمستخدم المجهول أو المسجل، ولا تُعاد أرقام الهواتف إلى المتصفح.
- السجلات القديمة صالحة؛ غياب إعداد المؤسسة أو القالب يعني القيمة الافتراضية المفعلة.
- لا إصلاح بيانات ولا seed؛ الترحيل قابل لإعادة تطبيق تعريفه بأمان.

### الاختبارات وحدود الدفعة

- الاختبار `119_notification_settings_test.sql` يعيد إنتاج فقدان حقول السياسة وفشل قبل
  الإصلاح.
- يضاف اختبار سلوكي لعقد الخدمة يثبت إيقاف القناة والقالب ووصول النص المخصص من مؤسسة
  الحدث نفسها.
- تعاد اختبارات سياق الإرسال، الصلاحيات، العامل، وسجل التوصيل، ثم فحص انجراف
  الترحيلات وبوابة حوكمة التطوير.
- لا تغيير في واجهة الإعدادات أو نصوص القوالب أو مزود واتساب في هذه الدفعة.
