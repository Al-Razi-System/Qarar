# خريطة أثر: معرف القرار وتنسيق تعليمات الموضوع

## رحلة المستخدم والثابت

- يفتح رئيس المجلس ملف موضوع مقترح قبل إدراجه في جدول الأعمال.
- يجب أن يميّز فوراً رقم الموضوع عن رقم القرار السابق الذي أوصل الموضوع إلى المجلس الحالي.
- تعليمات المناقشة المحفوظة بصيغة Markdown يجب أن تُعرض كمحتوى منسق وآمن في كل موضع قراءة، لا كرموز مصدر خام.
- العرض لا يغير النص المخزن ولا قرار المجلس ولا مرحلة الموضوع.

## المتصلون والمستهلكون

- نافذة `AgendaCandidateDetailsDialog` تعرض رأس ملف الموضوع وسياق القرار السابق.
- المكوّن المركزي `InstructionContent` مستهلك في تفاصيل المقترح وجدول الأعمال والغرفة الحية وتعليمات أنواع الموضوعات ونموذج تقديم الموضوع.
- المصدر هو `typed_creation_request.snapshot.authoring.discussion_instructions` أو نسخة تعليمات البند المخصصة.
- لا تغيير في عقود API/RPC أو الجداول أو الصلاحيات.

## الحالة والفشل والتوافق

- لا انتقال حالة في هذه الدفعة.
- النصوص الحديثة ذات بادئة `qarar:markdown:v1` تبقى كما هي.
- النصوص القديمة المستوردة التي تحتوي عدة علامات Markdown مهربة في بداية الأسطر تُفك تهريبات العرض فقط، دون تعديل القيمة المخزنة.
- أمثلة Markdown الحرفية غير المعلّمة بالبادئة، والمحتوى داخل الأسوار البرمجية، تبقى حرفية ولا تتحول إلى عناوين أو قوائم.
- HTML والروابط تظل خاضعة للتنقية الحالية ولا يسمح بإدراج سكربت أو تنسيق غير آمن.

## الاختبارات

- اختبار رجعي بقيمة التطوير الفعلية: بادئة Markdown، عناوين وقوائم وفواصل مهربة، بلا حاوية HTML.
- اختبار استمرار حفظ Markdown الحرفي والأسوار البرمجية.
- اختبار ظهور شارة «قرار سابق» في رأس ملف الموضوع مع بقاء سياق القرار التفصيلي.
- اختبارات النافذة والمكوّن المركزي وفحص TypeScript وESLint.
