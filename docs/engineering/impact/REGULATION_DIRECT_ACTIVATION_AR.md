# تفعيل البنود مباشرة دون مراجع آخر

## القرار والحدود

بناءً على طلب المستخدم نلغي خطوة المراجعة المستقلة من مكتبة اللوائح الجديدة.
المستخدم المخول بـ `governance.policies.manage` وقراءة اللوائح يستطيع نشر النص
وتفعيل أو تعطيل بند بنفسه. لا نغير صلاحيات الحسابات ولا نمنح القراء حق الكتابة.
العقود التشغيلية القديمة V1 ومراجعاتها تبقى متوافقة لحماية العمليات السابقة؛
لا تظهر خطواتها في الواجهة الجديدة ولا تستخدمها رحلة النشر المباشر.

## خريطة التأثير قبل التنفيذ

- الرحلة: إنشاء لائحة ← إضافة نص ← نشر مباشر أو تفعيل بند ← تعطيل/إعادة تفعيل.
- الثابت: النص المحفوظ للموضوع والقرار لا يتغير؛ إيقاف الاستخدام الجديد ليس حذفًا.
- المستدعون: صفحات اللوائح والقارئ ونافذة التأكيد، عميل المكتبة، API اللوائح،
  `api_v2.admin_save_regulation_library_v2` وقراءة التفاصيل والقائمة.
- الجداول: policies، policy_versions، policy_items، موروثات النسخة من البنود
  والمصادر والمرفقات والقواعد والنطاقات، topic_governance_mappings، إيصالات الأوامر
  وسجل التدقيق. نحافظ على UUID والمرجع النصي والعلاقات السابقة.
- الحماية: assert_policy_version_editable وpolicy_items_draft_guard يمنعان تعديل
  النسخة المنشورة. guard_policy_legislative_readiness للمراجعة القديمة لا يُلغى.
- المستهلكون المجاورون: مطابقة/اختيار سند الموضوع يرشح is_active، ويلزم الجاهزية
  التشغيلية القديمة؛ النشر المرجعي المباشر لا يدعي جاهزية محرك القواعد.
- الأدوار: مدير اللوائح مسموح، قارئ فقط/غير مخول/مؤسسة أخرى ممنوع. لا يلزم approve.
- لا توجد مهمة خلفية أو تعديل للاجتماعات أو الدعوات أو بيانات الإنتاج.

## الانتقالات والفشل

- نشر: مسودة مكتبة جديدة أو نسخة مكتبة معلقة بالمراجعة/معتمدة ← نافذة حالية؛
  النسخة النافذة السابقة تصبح محفوظة. لا يلزم مستخدم ثانٍ.
- تغيير حالة بند: مسودة قابلة للتعديل ← تحديث is_active ونشر النص ذريًا؛
  نص نافذ ← نسخة موروثة تلقائية ← تعديل حالة البند المناظر ← نشر ذري.
- إذا توجد تعديلات غير منشورة لا ننشرها ضمنيًا عند الضغط في النص الحالي؛
  يظهر تعارض يطلب فتح مسودة التعديل أولًا. النسخ القديمة للقراءة لا تتغير.
- التعطيل الأخير مسموح؛ وجود النص محفوظ حتى لو كانت جميع البنود معطلة.
- نشر نص فارغ أو نصوص فعلية فارغة ممنوع. الأكواد البرمجية لا تظهر للمستخدم.
- قفل اللائحة وإيصال الأمر وبصمة المراجعة يمنعان التكرار والكتابة المتعارضة.
  أي فشل يعيد النسخة/حالة البند/النشر/التدقيق/الإيصال معًا.
- ترحيل أمامي فقط؛ لا تحويل جماعي للسجلات القديمة أو حذف بيانات. المسودات القديمة
  المرتبطة بمحرك التشغيل تستخدم «بدء تعديل» لتكوين نسخة مكتبة مستقلة.
- الرجوع: إعادة تفعيل البند بأمر جديد مع حفظ تاريخ التعطيل، وليس محو التاريخ.

## الاختبار المطلوب

اختبار فاشل أولًا للنشر بنفس المستخدم وتغيير حالة البند؛ ثم المنع السياقي،
حماية النص السابق، آخر بند، تكرار الأمر، المراجعة المتعارضة، الملفات والعلاقات
الموروثة، المسودات السابقة، وفشل النص غير المكتمل. اختبار واجهة دون أزرار مراجعة،
تغيير الحالة داخل نافذة التأكيد مع بقاء الخطأ فيها، وتجربة المتصفح بحساب واحد
وعرض الهاتف وسطح المكتب. تشغيل اختبارات المكتبة والتوريث والمحرك والعقود،
typecheck وlint وdevelopment-governance وفحص تطابق الترحيلات قبل التسليم.

## التنفيذ والتحقق

- أضيفت ترحيلات أمامية 20261008010000 و11000 و12000 إلى قاعدة التطوير فقط؛
  لم تعدل أي ترحيلة مطبقة أو بيانات مؤسسة قائمة أو كلمة مرور/صلاحية مستخدم قائم.
- العقد الجديد يضيف `publish` و`set_item_active` بإدارة اللوائح دون صلاحية approve.
  العقود القديمة محفوظة خلف تنفيذ توافق داخلي غير متاح مباشرة للعملاء.
- قراءة التفاصيل ترجع `direct_activation_version_ids` لتطابق إتاحة الأزرار مع
  حماية الخادم. النص الحالي الذي لديه تعديلات معلقة لا ينشرها ضمنيًا.
- التوريث والنشر وحالة البند والتدقيق والإيصال داخل معاملة واحدة، مع قفل ينسق
  أيضًا مع إنشاء النسخ القديم. مرجع البند يستمر بينما UUID النسخة التاريخية محفوظ.
- اختبار 70 فشل أولًا قبل وجود الأوامر ثم نجح: 28 تحققًا تشمل مديرًا بلا approve،
  قارئًا ومؤسسة أخرى، تعطيل آخر بند، توريث المصدر والمرفق، إعادة التفعيل، إعادة
  المحاولة، تعارض المراجعة، منع المسودة الأقدم، وعدم إنشاء نسخة عند عدم تغير الحالة.
- اختبارات قاعدة البيانات 13 و30 و47 و57 و69 و70 نجحت: 126 تحققًا إجمالًا.
- اختبارات واجهة المكتبة وملفات المصدر وفهرسة البنود وAPI: 24 اختبارًا نجحت؛
  أزرار المراجعة غير موجودة، والخطأ يبقى داخل نافذة تغيير الحالة.
- تجربة المتصفح على devqarar بحساب اختبار واحد ومع MFA الطبيعي نجحت بعد آخر
  ترحيل: إضافة/تعديل/حذف نص، إعادة المحاولة، التنشيط، التعطيل، إعادة تحميل الصفحة،
  إعادة التفعيل، وراثة النص، أرشفة/استعادة، والتزامن عبر HTTP. الحساب المعزول عُطّل
  بعد الاختبار. الهاتف 390 بكسل وسطح المكتب 1365 بكسل دون تجاوز أفقي.
- typecheck نجح. lint: صفر أخطاء و6 تحذيرات قديمة خارج الملفات المعدلة لهذه الرحلة.
  development-governance وترميز الوثائق وdiff-check نجحت، وسجل الترحيلات يطابق
  231 ملفًا. هذه نتائج رحلة المكتبة وليست ضمانًا لجميع العمليات في النظام.
