# نموذج البيانات المستهدف لحوكمة الموضوعات – الإصدار الأول

## القرار المركزي

المسار يخص **نوع الموضوع** وليس بند اللائحة. بند اللائحة/السند يثبت مصدر الاختصاص أو شرط مرحلة أو موعداً أو وثيقة. قواعد الاجتماع والتصويت والمحضر والتكرار سياسات تشغيلية مستقلة، ولا تُخزن كمسارات موضوعات.

## الكيانات الأساسية

### `topic_classifications`

تصنيف هرمي للعرض والتقارير، مثل أكاديمي، طلابي، مؤسسي، جودة. لا يحدد المسار وحده.

- UUID داخلي.
- رمز ثابت واسم عربي.
- تصنيف أب اختياري.
- حالة ومدة سريان.

### `topic_types`

النوع الذي يختاره مقدم الموضوع، وهو مالك قاعدة المسار والجدولة.

- مرجع تلقائي `TYP-*`.
- التصنيف.
- الاسم والوصف.
- حوكمي أو غير حوكمي.
- حالة `draft/review/approved/effective/retired`.
- نسخة وتعريف مالك الاعتماد.

### `legal_authorities`

سجل مرجعي غير قابل للتعديل بعد الاعتماد يمثل المستند والمادة والبند والنص.

- UUID داخلي ومرجع `AUT-*`.
- معرف المصدر الخارجي، مثل `AUTH-0203`، في حقل مستقل.
- المستند ونسخته.
- المادة والبند والنص.
- نوع الصلاحية.
- درجة الثقة وحالة الاعتماد.
- بصمة نص تمنع الازدواج غير المقصود.

### `topic_type_authorities`

علاقة متعدد إلى متعدد بين نوع الموضوع والأسانيد.

- دور السند: اختصاص، وثيقة، توقيت، انتقال، قرار نهائي، اعتراض.
- هل هو إلزام قانوني أم مؤسسي أم إرشادي.
- مدة السريان والأولوية.

### `workflow_templates` ونسخها

القالب المجرد للمسار. النسخة الفعالة لا تعدل، والموضوع يأخذ لقطة منها عند الإنشاء.

### `workflow_steps`

كل مرحلة لها جهة واحدة ودور واحد، وليس سلسلة مجالس في حقل نصي.

- رمز المرحلة وترتيبها.
- فئة المجلس أو الجهة المسؤولة.
- الفعل: اقتراح، دراسة، توصية، موافقة، اعتماد، إحالة، تنفيذ.
- شروط الدخول والخروج.
- النتائج المسموحة.

### `workflow_step_authorities`

الأسانيد الخاصة بالمرحلة. يسمح بأن يكون لكل مرحلة سند مختلف داخل المسار نفسه.

### `workflow_transitions`

تحدد النتيجة التالية صراحة:

- قبول إلى الأمام.
- رفض مع إغلاق الموضوع.
- رفض مع إعادته للمرحلة السابقة.
- إحالة عكسية إلى مجلس أدنى.
- تصعيد شرطي.
- اكتمال نهائي.

### `topic_type_workflow_bindings`

يربط نوع موضوع واحدًا بنسخة مسار، مع مدة سريان وأولوية. هذا هو العقد الذي ينقص ملف Excel الحالي.

### `topic_schedule_policies`

سياسة موضوع غير مزمن أو ثابت التاريخ أو شهري أو فصلي أو موسمي أو محدود المدة.

- نافذة الإتاحة.
- الموعد المستهدف.
- آخر تأجيل.
- عدد مرات التأجيل.
- قاعدة اختيار الاجتماع المؤهل.
- منع إنشاء استحقاق مكرر للدورة نفسها.

### `meeting_policies`

سياسة مستقلة لكل نوع مجلس/اجتماع:

- التكرار والأسبوع المستهدف.
- مهلة إرسال جدول الأعمال.
- النصاب والتصويت.
- المرفقات والمصادقات.
- الاعتراض ومراجعة المحضر.

### `topic_prior_stage_claims`

طلب مقدم الموضوع لاستكمال مسار سابق خارج النظام. يراجع رئيس المجلس الحالي الأدلة ويقبلها أو يعيدها للاستكمال.

## الحدود مع النموذج الحالي

| الحالي | المستهدف |
|---|---|
| `topic_categories` | يبقى للتصنيف، ويضاف مفهوم مستقل لنوع الموضوع |
| `policy_items.topic_category_id` | يستبدل تدريجياً بعلاقة نوع الموضوع بالسند |
| `policy_items.workflow_template_version_id` | يستبدل تدريجياً بربط نوع الموضوع بنسخة المسار |
| قواعد اجتماع داخل بيانات المسار | تنقل إلى `meeting_policies` |
| موضوع/مسار مطابق بالاسم | ربط UUID مقيّد بمفاتيح أجنبية |

لا تحذف الحقول الحالية مباشرة. تضاف الجداول الجديدة أولاً، ثم قراءة مزدوجة في بيئة مرحلية، ثم ترحيل السجلات، ثم إيقاف العقود القديمة بإصدار مستقل.

## عقد التفعيل

لا يصبح نوع الموضوع فعالاً إلا إذا:

1. له تصنيف معتمد.
2. له سند اختصاص معتمد واحد على الأقل.
3. له نسخة مسار صحيحة تحتوي بداية ونهاية.
4. كل مرحلة لها جهة ودور ونتائج وانتقالات.
5. كل شرط إلزامي موصوف بسند أو اعتماد مؤسسي.
6. لا يوجد تعارض مفتوح أو تكرار غير محسوم.
7. اجتاز اختبار المسار الأمامي والرفض والعودة والاستكمال السابق.

## نتيجة مراجعة ملف «مصحح الربط»

- 39 سجلًا مقبولًا كأساس **سند مرجعي** فقط.
- ثلاثة موضوعات محجوبة: `NEW-0010`, `NEW-0018`, `NEW-0019`.
- أربعة قوالب مسار موضوع محجوبة عن التفعيل حتى تحديد `topic_type_code` والانتقالات.
- سبع سياسات تشغيلية مصنفة منفصلة: مراجعة محضر، أربعة تكرارات مجالس، اعتراض، وتنفيذ.
- لا يوجد استيراد أو تفعيل إنتاجي ضمن هذه الدفعة.
