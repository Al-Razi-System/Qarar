# مقترح سياسة المراجع السياقية والمرتبطة

## الهدف

إنشاء مراجع آلية تمكّن الموظف من معرفة نوع السجل وسياق نشأته وعلاقته بأصله، من دون مطالبة المستخدم بإدخال معرف، ومن دون استخدام المرجع المقروء بديلاً عن العلاقات الصحيحة في قاعدة البيانات.

## الهوية المزدوجة

لكل كيان:

1. `id`: UUID داخلي ثابت، وهو المستخدم في المفاتيح والعلاقات والصلاحيات.
2. `reference_number`: مرجع مقروء يولده الخادم/قاعدة البيانات آلياً.

المرجع المقروء يفيد البحث والعرض والتدقيق، لكنه لا يثبت وحده العلاقة أو الصلاحية.

## مستويات المرجع

### 1. كيان مستقل

الصيغة:

`ENTITY-CONTEXT-YEAR-SEQUENCE`

مثال مجلس قسم الذكاء الاصطناعي:

`CNL-DEP-AI-2026-0001`

مثال موضوع أنشئ في سياق المجلس نفسه:

`TOP-DEP-AI-2026-000123`

### 2. كيان تابع

الصيغة:

`CHILD-PARENT_REFERENCE-CHILD_SEQUENCE`

أمثلة:

- المرفق الرابع للموضوع: `ATT-TOP-DEP-AI-2026-000123-004`
- القرار الثاني الناتج عن الموضوع: `DEC-TOP-DEP-AI-2026-000123-002`
- التكليف الثالث الناتج عن القرار: `TSK-DEC-DEP-AI-2026-000091-003`
- محضر الاجتماع: `MIN-MTG-DEP-AI-2026-000045-001`

بهذا يمكن تمييز أن `ATT` مرفق، وأن أصله `TOP`، وأن سياق إنشاء الموضوع مجلس قسم الذكاء الاصطناعي، مع بقاء العلاقة الفعلية محفوظة بواسطة UUID.

## قاموس السياق

لا تكتب الأسماء العربية أو الإنجليزية الحرة داخل المرجع. تستخدم رموز ثابتة مع قاموس مستقل:

| الجزء | مثال | المعنى |
|---|---|---|
| نوع الجهة | `DEP` | قسم |
| رمز الجهة | `AI` | الذكاء الاصطناعي |
| نوع الكيان | `TOP` | موضوع |
| السنة | `2026` | سنة إنشاء السجل |
| التسلسل | `000123` | رقم ذري فريد ضمن النطاق المحدد |

رمز الجهة ثابت بعد اعتماده، ولا يتغير بتغيير اسم العرض. يمنع إعادة استخدام رمز جهة محذوفة لكيان آخر.

## البادئات المقترحة

| الكيان | البادئة |
|---|---|
| جهة تنظيمية | `ORG` |
| مجلس | `CNL` |
| نوع موضوع | `TYP` |
| موضوع | `TOP` |
| مرفق | `ATT` |
| لائحة | `REG` |
| إصدار لائحة | `REV` |
| سند/نص قانوني | `AUT` |
| مادة/بند | `ART` |
| قالب مسار | `WFL` |
| نسخة مسار للموضوع | `WFI` |
| مرحلة مسار | `STG` |
| اجتماع | `MTG` |
| بند جدول أعمال | `AGI` |
| محضر | `MIN` |

## قواعد الثبات

- يعكس المرجع **سياق الإنشاء** لا الموقع الحالي؛ تصعيد الموضوع إلى مجلس الكلية أو الجامعة لا يغير مرجعه.
- الانتقال الحالي والمسار الحالي يحفظان في حقول وعلاقات مستقلة، ولا يستنتجان من المرجع.
- لا تدخل الحالة مثل `approved` أو `draft`، ولا التصنيف القابل للتعديل، داخل المرجع.
- لا يغير تعديل الاسم أو نقل الجهة أو إعادة تصنيف الموضوع أي مرجع سابق.
- عند دمج سجلين يحتفظ مرجع السجل الملغى كمرجع بديل قابل للبحث مع حدث تدقيق.
- الاستيراد يحتفظ بمعرف المصدر في `external_reference` ولا يفرضه كمرجع النظام.
- توليد التسلسل ذري وآمن من التكرار، ولا يعتمد على `max + 1` غير المحمي.
- تمنع واجهات وواجهات API إدخال `reference_number` في الإنشاء العادي.

## قاعدة طول السلسلة

لمنع تضخم مرجع السجلات العميقة، تضمّن هوية الأصل الأقرب ذات القيمة العملية، ولا تكرر كامل شجرة النسب. مثال التكليف يستخدم مرجع القرار المختصر وسياق الجهة، بينما تحفظ السلسلة الكاملة (`task → decision → topic → meeting`) في العلاقات.

## ضوابط التطبيق

قبل اعتماد الصيغة نهائياً يجب:

1. جرد البادئات والمراجع الحالية وعدم كسر المراجع التاريخية.
2. اعتماد قاموس رموز الجهات والمجالس.
3. تحديد نطاق كل تسلسل: المؤسسة + نوع الكيان + السنة، أو الأصل للسجلات التابعة.
4. توفير بحث بالمرجع الكامل والجزئي والمرجع التاريخي.
5. اختبار الإنشاء المتزامن، النقل، التصعيد، الدمج، والاستيراد.
6. عرض اسم عربي واضح بجانب المرجع دائماً؛ المرجع ليس بديلاً عن اسم العرض.
