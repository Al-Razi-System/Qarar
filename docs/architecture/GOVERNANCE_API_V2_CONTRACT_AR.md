# عقد API المستهدف لنموذج الحوكمة V2

## الحالة

العقد منفذ في `api_v2`. إصدار التأليف المحدود يمنح `authenticated` تنفيذ
`get_governance_authoring_options_v2` و`save_governance_bundle_draft_v2` فقط، مع
التحقق السياقي داخل الخادم. لا يمنح `anon` أي تنفيذ، ولا توجد صلاحية وصول مباشر
للمستخدمين إلى جداول V2. أوامر التحقق والإرسال وطلب التعديل والاعتماد والتفعيل
تبقى محجوبة إلى أن تجتاز كل مرحلة بوابة إصدار مستقلة.

## مبدأ الواجهة

لا نقدم CRUD مباشراً لكل جدول؛ نقدم «حزمة حوكمة» تجمع نوع الموضوع وإصداره وأسانيده ومساره وجدولته، حتى لا يحفظ جزء صالح بجانب أجزاء ناقصة. الحفظ مسودة، ثم التحقق، ثم الإرسال، ثم اعتماد مستقل، ثم تفعيل بتاريخ سريان.

عمليات الأوامر:

1. `save_governance_bundle_draft_v2`
2. `validate_governance_bundle_v2`
3. `submit_governance_bundle_v2`
4. `request_governance_bundle_changes_v2`
5. `approve_governance_bundle_v2`
6. `activate_governance_bundle_v2`

عمليات القراءة:

1. `get_governance_authoring_options_v2`
2. `get_governance_bundle_v2`
3. `list_effective_topic_types_v2`
4. `preview_topic_route_v2`

تعيد `get_governance_authoring_options_v2` التصنيفات غير المتقاعدة ونسخ المسارات
الفعالة والمتحقق منها فقط، مع خطواتها مرتبة. لا يجوز للواجهة اختراع معرف مسار أو
حفظ اسم عرض بدلاً من معرف نسخة المسار.

## قواعد الأوامر

- كل أمر كتابة يستخدم `client_request_id` ويحفظ نتيجة إعادة الطلب نفسها.
- العميل لا يرسل `id` أو `reference_number` أو حالة الاعتماد أو علم التفعيل.
- يرسل اختيار المسار في `workflow.workflow_template_version_id` من قائمة خيارات الإعداد فقط،
  ويرسل الجدولة في `schedule.rule_type` و`schedule.rule_config`. يحفظ الخادم الهوية
  والمسار والجدولة في معاملة واحدة أو يتراجع عنها كلها.
- التصنيف قاموس مشترك: يعاد استخدامه بالرمز ولا يعاد إنشاؤه أو تغيير اسمه ضمن
  مسودة نوع موضوع. تغيير تصنيف المسودة يغيّر الربط فقط.
- حظر المعرّفات يخص محتوى `bundle`؛ عند تعديل مسودة موجودة يرسل العميل
  `bundle_id` كمعامل أمر منفصل مع `expected_lock_version`. غيابهما يعني إنشاء مسودة جديدة.
- كل أمر يتحقق من صلاحية سياقية، وقفل تعارض، ونسخة السجل المتوقعة.
- الاعتماد منفصل عن الإعداد، والتفعيل منفصل عن الاعتماد.
- يتطلب التفعيل `bundle_id` و`expected_lock_version` و`effective_from` و`client_request_id`.
- التفعيل يفشل إذا غاب سند اختصاص أو مسار صالح أو انتقال نتيجة أو سياسة جدولة صريحة.
- الاستجابة تعيد `trace_id` دائماً، مع رسالة عربية آمنة وأخطاء حقول عند التحقق.

## واجهة إنشاء الموضوع

تعرض `list_effective_topic_types_v2` الأنواع الفعالة المتاحة لوحدة المنشأ فقط. بعد اختيار النوع تعرض `preview_topic_route_v2` المسار والوثائق والتوقيت والنتائج النهائية قبل الإنشاء. لا يختار المستخدم سنداً أو إصدار مسار يدوياً ولا يدخل معرفاً.

## عرض الخطأ

رمز الخطأ عقد داخلي ثابت، والنص العربي هو النص المعروض. لا تعرض رسالة PostgreSQL أو اسم constraint أو enum. عند فشل نموذج أو نافذة منبثقة تظهر الرسالة وأخطاء الحقول داخلها، مع بقاء المدخلات وإتاحة إعادة المحاولة الآمنة.

## شرط التنفيذ

لا تنشأ RPC قبل إضافة جدول حزمة/مراجعة أو تعريف معاملة مكافئة، وتوفير اختبارات: السماح والمنع، الاعتماد الذاتي، تعارض نسختين، إعادة الطلب، تداخل السريان، وفشل منتصف المعاملة.

## حدود إصدار التأليف الحالي

- تعرض الواجهة الخيارات الفعلية وتحفظ مسودة الهوية والتصنيف والمسار والجدولة في معاملة واحدة.
- لا تمكّن الواجهة أي إجراء مراجعة أو اعتماد أو تفعيل.
- تمر الطلبات عبر Route Handler يتحقق من الجلسة وCSRF ويعيد رسالة عربية آمنة و`trace_id`.
- يتطلب التشغيل أن يكون مخطط `api_v2` ضمن مخططات PostgREST المعروضة؛ منح قاعدة البيانات وحده لا يكفي.
