# معيار المعرّفات التلقائية

## القرار المعماري

لا يطلب النظام من المستخدم إدخال معرف لأي كيان. لكل سجل هويتان:

1. `id`: مفتاح UUID داخلي ثابت لا يظهر كمدخل ولا يحمل معنى تجارياً.
2. `reference_number`: مرجع مقروء ينشئه الخادم أو قاعدة البيانات تلقائياً بحسب نوع الكيان.

## الصيغة

الصيغة القياسية: `PREFIX-YEAR-SEQUENCE`، مثل `TOP-2026-000123`.

| الكيان | البادئة |
|---|---|
| موضوع | `TOP` |
| لائحة | `REG` |
| إصدار لائحة | `REV` |
| بند لائحة | `ART` |
| اجتماع | `MTG` |
| قرار | `DEC` |
| تكليف تنفيذ | `TSK` |
| طلب استثناء | `EXC` |
| مسار اعتماد | `WFL` |
| حزمة حوكمة V2 | `GVB` |
| مجلس | `CNL` |
| وحدة تنظيمية | `ORU` |
| نوع وحدة تنظيمية (رمز مولد) | `OUT` |
| خطة اجتماعات مجلس | `MTP` |
| مجال الموضوع (التصنيف العام) | `TCL` |
| نوع الموضوع (تصنيف قابل للمعالجة) | `TYP` |
| نسخة نوع الموضوع | `TVR` |
| منح نطاق تقديم مستخدم | `SPG` |

رمز نوع الموضوع التقني يشتق داخليًا من مرجعه نفسه: `TYP-2026-000001` يصبح
`typ_2026_000001`، ولا يدخله العميل. لا يحمل المجال المتغير في الهوية الثابتة؛
علاقة النوع بالمجال محفوظة بواسطة UUID. الرموز التاريخية باقية دون إعادة ترميز.

إضافة نوع جديد تتطلب تسجيل بادئته هنا ومنع تعارضها مع الموجود.

## قواعد إلزامية

- التوليد ذري وآمن عند التزامن، ولا يعتمد على `max + 1` خارج قفل أو تسلسل آمن.
- المرجع فريد داخل المؤسسة ونوع الكيان، ولا يعاد استخدامه بعد الحذف.
- السنة جزء من العرض ولا تعني إعادة استخدام تسلسل قديم بطريقة تسبب تعارضاً.
- لا يُسمح للعميل بإرسال مرجع يختاره المستخدم في عمليات الإنشاء العادية.
- العلاقات تستخدم UUID، لا المرجع المقروء.
- تغيير عنوان أو تصنيف السجل لا يغير مرجعه بعد الإنشاء.
- الاستيراد التاريخي يحفظ المرجع الأصلي في حقل مستقل إن وجد، ويظل المرجع النظامي تلقائياً.
- يجب اختبار طلبات إنشاء متزامنة واختبار غياب الحقل من الواجهة وعقد API.

## قرار يحتاج تدقيقاً قبل التطبيق الشامل

يجب جرد البادئات الحالية والتسلسلات الموجودة في قاعدة البيانات قبل إنشاء ترحيل موحد، حتى
لا نكسر المراجع التاريخية أو العقود المستخدمة حالياً.
