# مصفوفة الحالات والصلاحيات المستهدفة

## قاعدة الصلاحية

لا تمنح أي عملية بسبب اسم دور عام فقط. القرار يكون: **فاعل + فعل + مورد + سياق + حالة**. مثال: امتلاك `meetings.manage` لا يجعل المستخدم رئيساً لكل مجلس، وامتلاك صلاحية الحوكمة لا يجعله المراجع الأساسي لاستكمال مسار موضوع وجهته مجلس آخر.

## العمليات الحرجة

| العملية | الفاعل الأساسي | السياق | أهم الشروط | الأثر الذري |
|---|---|---|---|---|
| إنشاء موضوع | مقدم مخول | وحدة المنشأ | نوع ومسار فعالان ونافذة صحيحة | إنشاء الموضوع ولقطة العقود وفتح أول مرحلة |
| إرسال استكمال سابق | مقدم الموضوع | الموضوع | دليل لكل مرحلة | إرسال وإشعار رئيس مجلس الوجهة |
| مراجعة الاستكمال | رئيس مجلس الوجهة الحالي | المجلس الوجهة | الطلب مرسل، ليس مقدم الطلب، والمسار لم يتغير | اعتماد المراحل وفتح أول مرحلة متبقية |
| إنشاء اجتماع حوكمي | مدير/رئيس المجلس المخول | المجلس | سياسة فعالة وموعد صالح | اجتماع مجدول فقط |
| إنشاء اجتماع مخصص | منشئ مخول | المؤسسة/وحدته | المشاركون ضمن النطاق | اجتماع مخصص مجدول |
| إضافة بند | مدير جدول الأعمال | الاجتماع المحدد | الاجتماع قابل للتحرير والموضوع مؤهل | ربط بالاجتماع المحدد فقط |
| بدء اجتماع | رئيس المجلس أو مضيف المخصص | الاجتماع | الحالة والنصاب والسياسة | بدء صريح مع وقت البدء |
| إصدار تكليف | رئيس المجلس المصدر/صاحب القرار | القرار | قرار معتمد، مكلف ومتحقق وموعد | إصدار وإشعارات |
| قبول التكليف | ممثل المكلف | التكليف | صادر وينتمي للمكلف | إثبات الاستلام |
| رفع الإنجاز | ممثل المكلف | التكليف | تقرير وأدلة مطلوبة | إرسال للتحقق |
| التحقق | الجهة المحددة | التكليف | بانتظار التحقق | إكمال متحقق أو طلب مراجعة |

مسؤولو النظام والحوكمة يملكون رقابة مدققة، لكن التدخل الاستثنائي يتطلب سبباً ويسجل كحدث مستقل، ولا يطمس هوية صاحب الصلاحية الأصلية.

## حالات الموضوع والمسار

- نوع الموضوع: `draft → review → approved → effective → retired`، ولا يعدل الإصدار الفعال.
- الموضوع يأخذ لقطة من نوعه ومساره وأسانيده وسياسته عند الإنشاء.
- خطوة المسار: معلقة، نشطة، بانتظار استكمال، مكتملة، معادة، متجاوزة بدليل معتمد، أو ملغاة.
- الانتقال العكسي ينشئ انتقالاً مدققاً ولا يمحو تاريخ المراحل السابقة.
- النتيجة النهائية لا تستنتج من نص حر؛ يجب أن يكون لها انتقال معرف مسبقاً.

## حالات الاجتماع

قاعدة التكرار والاستحقاق والاجتماع ثلاث حقائق مختلفة. وصول الموعد لا يجعل الاجتماع منعقداً. التسلسل الأساسي:

`draft → scheduled → ready_to_start → in_progress → waiting_for_minutes → waiting_for_approval → closed`

مع حالات `cancelled` و`archived` وفق شروط صريحة. الانتقال إلى `in_progress` يحتاج عملية بدء مصرحاً بها. لا تنشأ بنود جدول الأعمال في كل تكرارات السلسلة.

## حالات التكليف

`draft → issued → accepted → in_progress → submitted_for_verification → verified_complete`

ويمكن من التحقق الانتقال إلى `needs_revision` ثم العودة إلى التنفيذ. `overdue` مؤشر زمني لا يسمح بإغلاق المهمة تلقائياً. الإلغاء يحتاج سبباً وصلاحية وسجل تدقيق.

## عقد الأخطاء وتجربة المستخدم

كل mutation لها `client_request_id` لمنع التكرار، وقفل/تحقق تعارض، ومعاملة ذرية، وحدث تدقيق. تعرض حالات الانتظار والنجاح والتحقق والتعارض وفشل الخادم **في مكان الزر أو النموذج نفسه**. إذا كان الإجراء داخل نافذة منبثقة يبقى الخطأ داخلها. يمنع عرض أسماء enums أو SQL أو الرسائل الإنجليزية الخام.

الزر الذي سيرفضه الخادم بصورة متوقعة لا يظهر مفعلاً؛ يعرض بجانبه الشرط الناقص، مثل «لا يمكن بدء الاجتماع قبل اكتمال النصاب» أو «يلزم تقرير إنجاز ودليل واحد».
