# التشغيل والمراقبة

## Logs

تستخدم خدمات لوحة التحكم سجلات JSON موحدة تحتوي على `timestamp` و`level` و`event`. يجب تمرير `requestId` في العمليات التي تبدأ من HTTP، وعدم تسجيل رموز الدخول أو محتوى الاجتماعات أو مفاتيح الخدمات.

## Metrics

يعرض المسار الداخلي `/api/metrics` عدادات العمليات وإحصاءات زمن التنفيذ. في الإنتاج يجب ضبط `METRICS_TOKEN` وحماية المسار من خلال بوابة الشبكة، ثم إرساله في رأس `x-internal-metrics-token`. هذه المقاييس داخلية للعملية؛ يجب ربطها بمجمع خارجي عند التشغيل متعدد النسخ.

## Health checks

يُستخدم `/api/health` لفحص توفر لوحة التحكم. أما جاهزية قاعدة البيانات فتُقاس باختبارات Docker وعقود Supabase في CI.

## حماية تسجيل الدخول

عدادات محاولات الدخول محفوظة في Redis المشترك، وليست في ذاكرة عملية لوحة التحكم. راقب صحة خدمة `login-rate-limit-redis` ونسبة استجابات `429` و`503` لمسار `/api/auth/login`؛ ارتفاع `503` يعني أن الرأس الداخلي الذي يكتبه الـReverse Proxy أو Redis غير متاح ويجب علاجه قبل إعادة فتح المرور. لا تسجل البريد أو عنوان IP الخام عند التحقيق؛ مفاتيح Redis مشتقة بـHMAC وتنتهي تلقائيًا.

## Incident checklist

1. احفظ `requestId` من الاستجابة.
2. راجع السجل المنظم حسب `event` والزمن.
3. تحقق من `/api/health` ثم حالة Docker/Supabase.
4. لا تنسخ أسرار البيئة أو بيانات الاجتماع إلى التذاكر.
