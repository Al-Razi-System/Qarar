# تحقق فصل ترتيب المسار عن سياسة نوع الموضوع

## النطاق المنفذ

- قالب مشترك لترتيب المجالس فقط، غير قابل للتشغيل مباشرة كسياسة قرار.
- عمل المجلس ونتيجتا القبول والرفض لكل مرحلة داخل نوع الموضوع.
- حفظ نسخة تنفيذية مستقلة لكل نوع، بمعاملة واحدة وتكرار آمن وحماية التعارض.
- إبقاء القوالب القديمة والعمليات الجارية دون تحويل تلقائي أو حذف.
- تعطيل أزرار البدء قبل جاهزية المتصفح، لمنع ضياع النقرة الأولى.

## أدلة التحقق على التطوير المعزول

- `72_route_designer_test.sql`: نجحت 35 حالة، منها نوعان يستخدمان ترتيبًا واحدًا
  وينتهيان في مراحل مختلفة، العزل والصلاحيات، التكرار، ومنع تشغيل قالب الترتيب.
- اختبارات قاعدة البيانات المجاورة 18 و56 و58 و64: نجحت 40 حالة.
- اختبارات واجهة المسارات والتصنيف وAPI: نجحت 12 حالة. أعيدت بتشغيل عامل واحد
  ومهلة 60 ثانية بعد انتهاء مهلة التشغيل المتوازي بسبب بطء بيئة الاختبار.
- `npm run test:governance-v11-contracts`: نجحت 79 حالة.
- فحص متصفح فعلي على نطاق التطوير بهوية ومؤسسة اختبار معزولتين: إنشاء ترتيب
  بمجالس غير نشطة، حفظ وفشل ظاهر وإعادة محاولة بنفس المفتاح، إعادة تحميل وتنشيط،
  ثم اختيار الترتيب في نوع موضوع وحفظ سياسة إنهاء مبكر؛ كذلك التزامن والتعارض.
- لقطات سطح مكتب 1440 وجوال 390 للمسارات والسياسات، دون تمرير أفقي زائد.
- typecheck ناجح؛ lint العام دون أخطاء، مع ستة تحذيرات سابقة خارج نطاق التغيير.
- فحص حوكمة التطوير وترميز الوثائق ناجح.
- تطابق بصمات 237 ترحيلًا في قاعدة التطوير. بصمة seed مختلفة عن الملف المحلي؛
  لا تُستبدل البصمة ولا يعاد زرع البيانات لإخفاء الفرق. يلزم تسوية مصدر التهيئة
  قبل إصدار إنتاجي، ولا تمثل هذه الحزمة تصريحًا للنشر.

## ما لم يُنفذ أو يُختبر ضمن هذه الحزمة

الإحالة من الاجتماع بعد المناقشة مؤجلة لمرحلة الاجتماعات، وتتطلب صلاحيات سياقية
وسجل انتقال وأثرًا بالمحضر. لم تُختبر رحلة اجتماع وتصويت ومحضر كاملة بالسياسات
الجديدة؛ اختبارات الحفظ والعقود لا تعني ضمان خلو كل النظام من الأخطاء.
قائمة أنواع الموضوعات وإعادة فتح المسودات والتوقيت المتقدم تحتاج استكمالًا مستقلًا؛
الحزمة الحالية تحقق إعداد السياسة وحفظها ولا تدّعي اكتمال إدارة الأنواع بالكامل.
لم تُعدّل بيانات الجامعة الفعلية أو قاعدة الإنتاج. عُطلت هويات الاختبار المؤقتة
مع الاحتفاظ بالأدلة التدقيقية.

## تجربة المستخدم

1. افتح `/admin/workflows`، أنشئ ترتيبًا من مجلسين، احفظه ونشّطه.
2. افتح `/admin/governance-model` ثم «إنشاء نوع موضوع» وأدخل الهوية.
3. اختر المسار، وحدد عمل كل مجلس ونتيجتي القبول والرفض، ثم احفظ المسودة.
4. جرّب نوعًا ثانيًا بنفس المسار وسياسة مختلفة؛ يجب ألا تتغير سياسة النوع الأول
   أو ترتيب المسار المشترك.
