# دليل إدارة المجالس

## الغرض والحدود

يوضح هذا الدليل آلية إنشاء المجالس وإدارة بياناتها المرجعية والإدارية بحيث تستطيع بقية كيانات
النظام الإشارة إلى مجلس صالح عبر عقد موحد. لا تتضمن هذه الوحدة سياسات الاجتماعات أو الحضور أو
النصاب أو التصويت أو المحاضر أو اللوائح أو التغطيات.

## دورة العمل

1. يهيئ مسؤول الحوكمة نوع المجلس عبر عقود أنواع المجالس.
2. ينشئ المجلس بحالة `inactive` ومفتاح طلب فريد.
3. يضيف الأعضاء وفترات عضويتهم.
4. يعيّن الرئيس والمقرر من أعضاء المجلس الفعالين.
5. ينفذ فحص الاكتمال الإداري ويعالج رموز النقص.
6. يفعّل المجلس عندما تصبح نتيجة الفحص `ready=true`.
7. تستخدم الكيانات الأخرى `get_available_councils` لاختيار مجلس فعال.
8. يمكن تعطيل المجلس إداريًا، أو أرشفته نهائيًا بعد معالجة المجالس التابعة.

## أنواع المجالس

- `admin_search_council_types`: بحث مرقم داخل المؤسسة.
- `admin_create_council_type`: إنشاء نوع مخصص فعال وغير نظامي.
- `admin_update_council_type`: تعديل الاسم والوصف باستخدام `updated_at`.
- `admin_deactivate_council_type`: تعطيل نوع غير نظامي وغير مستخدم.

النوع النظامي لا يعدل ولا يعطل. النوع المرتبط بأي مجلس لا يعطل حتى لا تُكسر البيانات المرجعية.

## إنشاء المجلس وتعديله

يعرض `get_council_form_options` الأنواع الفعالة والمجالس التي تصلح أبًا والتصنيفات الإدارية
وأدوار القيادة. ينشئ `admin_create_council` المجلس بحالة `inactive`.

يجب إرسال `p_client_request_id`. تقفل قاعدة البيانات المفتاح داخل المعاملة، ويضمن الفهرس الفريد
عدم إنشاء سجلين للمؤسسة والمستخدم والطلب نفسه. إعادة الطلب تعيد المجلس الأصلي مع
`idempotent_replay=true` ولا تنشئ حدث Audit إضافيًا.

يوفر `admin_search_councils` بحثًا مرقمًا، ويعيد `admin_get_council_detail` النوع والأب والتصنيف.
يعدل `admin_update_council` البيانات الإدارية فقط، ويتطلب قيمة `p_expected_updated_at` الحالية.
عند اختلافها يعاد خطأ SQLSTATE `40001` وعلى العميل إعادة تحميل السجل.

## المرجع الموحد

يعيد `get_available_councils` المجالس ذات الحالة `active` داخل مؤسسة المستخدم فقط. يدعم مرشحات
النوع والتصنيف والأب والبحث النصي والترقيم. هذا العقد يثبت صلاحية المرجع فقط؛ لا يمنح المستهلك
صلاحية تنفيذ عملية أخرى على المجلس.

## الشجرة والنقل

يعيد `admin_get_councils_tree` قائمة مرتبة بالمسار، مع `path_ids` و`path_names` و`level_no`.
ينقل `admin_move_council` فرعًا كاملًا داخل معاملة واحدة، ويحدث مستويات الأحفاد ويسجل الأب السابق
والجديد وسبب النقل. يرفض:

- جعل المجلس أبًا لنفسه.
- النقل تحت أي ابن أو حفيد.
- الأب المؤرشف أو التابع لمؤسسة أخرى.
- الطلب المبني على `updated_at` قديم.

## العضويات

تستخدم إدارة المجالس جدول `qarar_iam.memberships` نفسه ولا تنشئ نموذجًا موازيًا:

- `admin_list_council_members`
- `admin_add_council_member`
- `admin_update_council_membership`
- `admin_end_council_membership`

تفرض قاعدة البيانات عدم تداخل فترتين للمستخدم والدور والمجلس نفسه. تاريخا البداية والنهاية
شاملان. العضوية المستقبلية أو المنتهية تظهر في التاريخ عند الطلب لكنها لا تكون فعالة ولا تمنح
صلاحية. التعديل لا يغير `user_id` أو `role_id`؛ لتغيير أحدهما تُنهى العضوية ثم تنشأ عضوية جديدة.

## القيادة

يقبل `admin_assign_council_leadership` الدورين فقط:

- `council_chair`
- `council_rapporteur`

يجب أن يكون الشخص عضوًا فعالًا بدور غير قيادي في تاريخ النفاذ. ينهي العقد فترة القائد السابق
قبل بدء الجديد ويحفظ السجلين. لا يجمع الشخص الدورين إلا إذا كانت
`allow_dual_leadership=true`. إعادة التعيين الفعال نفسه تعاد كطلب مكرر دون تغيير جديد.

## الاكتمال الإداري

يعيد `admin_validate_council_administrative_readiness` النتيجة ولا يغير حالة المجلس. تكون
`ready=true` فقط عند تحقق:

- نوع مجلس فعال.
- تصنيف إداري فعال.
- عدد أعضاء فعالين لا يقل عن `minimum_active_members`.
- رئيس فعال.
- مقرر فعال.
- عدم ازدواج الرئيس والمقرر إلا عند السماح الصريح.

كل نقص يعاد داخل `errors` برمز ثابت يمكن للواجهة ترجمته وعرضه. لا يفحص العقد اجتماعًا أو حضورًا
أو نصابًا أو تصويتًا.

## دورة الحالة

- `admin_activate_council`: يشترط اكتمالًا إداريًا كاملًا.
- `admin_deactivate_council`: يعيد المجلس إلى `inactive` بسبب إداري إلزامي.
- `admin_archive_council`: انتقال نهائي؛ لا يسمح به مع أبناء غير مؤرشفين.

كل انتقال يتطلب السبب و`p_expected_updated_at`. تحفظ الحالة الحالية على المجلس، ويحفظ كل انتقال
في `governance_unit_status_history`، ويسجل حدث Audit مستقل.

## الأمان والأخطاء

### مصفوفة الصلاحيات

لا تستخدم الوحدة صلاحية شاملة واحدة. يفحص كل عقد أقل صلاحية لازمة:

| الصلاحية | العمليات |
|---|---|
| `governance.units.read` | البحث والتفاصيل والشجرة وفحص الاكتمال |
| `governance.units.manage` | إنشاء المجلس وتعديله ونقله |
| `governance.units.activate` | التفعيل والتعطيل |
| `governance.units.archive` | الأرشفة النهائية |
| `governance.unit_types.manage` | إنشاء أنواع المجالس وتعديلها وتعطيلها |
| `governance.memberships.read` | قراءة العضويات الحالية والتاريخية |
| `governance.memberships.manage` | إضافة العضوية وتعديلها وإنهاؤها |
| `governance.leadership.assign` | تعيين الرئيس أو المقرر واستبداله |

تُنشأ هذه الصلاحيات مع دوري `council_chair` و`council_rapporteur` تلقائيًا لكل مؤسسة جديدة.
صلاحية `governance.councils.manage` القديمة معطلة ولا تستخدمها عقود الوحدة.

### الضمانات الزمنية والذرية

- لا تمنح العضوية صلاحية قبل `start_date` أو بعد `end_date`، حتى لو بقيت حالتها `active`.
- يمنع قيد قاعدة البيانات وجود رئيسين أو مقررين تتداخل فترات تكليفهما، بما في ذلك الكتابة
  الداخلية المباشرة أو الطلبات المتزامنة.
- استبدال القائد ينهي فترة القائد السابق ثم يضيف الجديد داخل المعاملة نفسها.
- سجل `governance_unit_status_history` للإضافة فقط؛ ترفض قاعدة البيانات `UPDATE` و`DELETE`.
- يرفض فحص الاكتمال تعدد الرئيس أو المقرر، والأب غير الصالح، والدورة في شجرة المجالس.
- يجب أن يطابق رمز المجلس `^[a-z][a-z0-9_]*$`، وأن يكون دور العضوية بنطاق
  `governance_unit`.

### Pagination

تعيد عقود القوائم `items` و`total` و`limit` و`offset`. الترتيب ثابت ويستخدم `id` فاصلًا
نهائيًا عند تساوي القيم، والحد الأعلى للصفحة 100.

جميع العقود تعمل عبر `api_v1` فقط. لا يملك `authenticated` تنفيذ دوال الوحدات الداخلية أو
الكتابة المباشرة على الجداول. تستخرج المؤسسة والفاعل من JWT ولا يقبل `organization_id` من العميل.

أهم SQLSTATE:

- `22023`: مدخلات أو انتقال غير صالح.
- `23503`: مرجع مفقود أو عابر للمؤسسات.
- `23514`: قاعدة إدارية غير متحققة.
- `23P01`: تداخل فترات العضوية.
- `40001`: تعارض Optimistic Concurrency.
- `42501`: صلاحية غير كافية.
- `P0002`: السجل غير موجود داخل المؤسسة.
- `55000`: عملية ممنوعة على مجلس مؤرشف.

## قاعدة تكامل الواجهات

تحفظ الواجهة `updated_at` من آخر قراءة وترسله في أوامر التعديل والنقل والحالة. عند `40001` تعيد
تحميل التفاصيل ولا تعيد إرسال البيانات القديمة تلقائيًا. يجب التعامل مع المصفوفات الفارغة كـ`[]`
وتجاهل الحقول الإضافية مستقبلًا مع رفض غياب حقول الهوية والحالة الأساسية.
