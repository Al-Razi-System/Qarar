# دليل الصلاحيات النظامية

الترحيل `20261010018000_system_permission_catalog` يسجل 61 تعريفًا ثابتًا
للعقود القائمة، دون منحها لأي دور. الدليل الداخلي ليس RPC للمستخدم.
واجهة الإدارة تستعمل `admin_list_permissions` القائمة وأسماء عربية فقط.

- المؤسسات الجديدة تُهيَّأ تلقائيًا ضمن معاملة إنشاء المؤسسة النظامية.
- المؤسسات السابقة تتلقى التعريفات المفقودة فقط؛ المعرفات والأسماء المخصصة
  والتعريفات المعطلة والنطاقات السابقة والمنح وطلبات الاعتماد محفوظة.
- التكرار لا يضيف تعريفًا أو حدث تدقيق ثانيًا. الصيانة خاصة بمالك IAM/الترحيلات.
- الاختيارات تصبح منحًا بعد رحلة تغيير الصلاحيات والاعتماد القائمة، لا عند
  تهيئة الدليل. وتبقى شروط المجلس والرئيس والمقرر والحضور وحالة العملية.
- التعريفات التاريخية مثل `decisions.create` و`iam.approvals.review`
  محفوظة للتوافق؛ ليست بديلًا عن سلطات السياق أو بوابة العقد الفعلية.
- لا تُستحدث أذونات وهمية للمحاضر والتنفيذ: العقود القائمة تتحقق من أدوار
  الاجتماع والمصادقة ومن المكلفين. لا تُحول أسماء أحداث التدقيق إلى أذونات.
- أسماء ونطاقات التعريفات التالية هي القيم الافتراضية للمؤسسات الجديدة؛
  لا يعيد الترحيل كتابة قيم مؤسسة سبق إعدادها.

## التحقق

`supabase/tests/database/92_system_permission_catalog_test.sql` يختبر
الاكتمال مقابل جميع بوابات الصلاحيات النصية المثبتة في قاعدة البيانات، التكرار،
حفظ التعريفات السابقة والمعطلة، عدم منح الأدوار، عزل المؤسسات ونطاق المجلس.
اختبار المتصفح `scripts/test-administrative-roles-dev-browser.mjs` لا يزرع
تعريفات يدويًا: يعتمد على تهيئة المؤسسة الجديدة، ثم يختبر الطلب والاعتماد
والرفض والتعطيل وإعادة التفعيل ضمن بيانات معزولة في التطوير فقط.
